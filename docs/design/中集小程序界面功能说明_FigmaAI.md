# 中集内部调度系统｜小程序界面功能说明

> 当前执行范围（2026-09-19）：现阶段只做标准版功能，其他不做。额外能力仅留档，不作为待执行任务。已要求的日常业务迁移小程序继续保留。

用途：交给 Figma AI 生成微信小程序页面与交互原型。  
整理日期：2026-09-18。  
版本：V3.2，本期业务范围收敛版（支持一人多角色）；修订日期：2026-09-19。

需求依据：《中集内部调度系统需求文档》V1.0，以及用户最新指示「日常业务操作相关的都放到小程序，非业务相关的放到管理平台」。端划分以《中集系统功能端划分建议》V2.2 为准，替代此前全部功能均放手机的方案。本次用户同意将额外能力移入《中集待确认扩展功能清单》，不计入本期页面、业务入口或验收。原文继续约束已知业务规则及车辆条件；原需求与报价保留为历史基线，端迁移不代表新增能力获批。

本文件仅用于生成小程序业务界面。工人、仓库、调度在手机完成全部日常操作，具备全厂查询权限的人员可查看业务概览；人员权限、基础资料、基础业务规则、管理报表及系统审计移至管理平台。页面布局为设计建议，额外能力仅保留在独立待确认文档与画板页。

## 1. 给 Figma AI 的总体指令

请基于本文件设计「中集内部调度系统」微信小程序，面向工厂内部工人、仓库人员、调度人员和管理员，完成申请、审批、合单装货、选车派单、车辆监控与控制、取货、异常处理、日常业务统计、记录查询及九识普通首页跳转。

请生成可点击的中文移动端原型，主画板建议为 390 × 844，适配常见手机宽度并预留微信导航栏、右上角胶囊和底部安全区。风格建议清晰、简洁、适合工厂现场：浅色背景，蓝色主操作，绿色成功，橙色提醒，红色失败；文字与按钮易辨认。颜色、尺寸和布局均为设计建议，无已确认品牌规范，不虚构中集官方标识。

采用一个小程序、四种角色工作区。工人底部导航为「申请／订单／消息／我的」，首页为申请表单；仓库为「工作台／配送批次／消息／我的」；调度为「调度台／车辆／消息／我的」；有全厂查看权限的人员使用业务概览工作区「概览／业务记录／消息／我的」。首页顶部和个人中心提供已授权角色切换，不允许自行获得新权限。扫一扫在工人首页、待取货详情和车辆工作区提供。二级页面使用返回导航，操作栏避开底部安全区。手机管理列表使用卡片、筛选抽屉和分步表单，避免缩小桌面表格。

请同时生成四种工作区的主要页面、关键状态变体、选择弹层和确认弹窗；连接第 6 节 A–H、J 共九条本期流程。不要只生成静态首页。所有业务说明使用工人能理解的中文，不展示接口名、任务技术标识、消息协议或密钥等实现细节。

### 本版界面范围与能力标注

- **原有业务迁移**：仓库工作台、受理驳回、合单装货、选车派单、任务取消、工单处理、日常业务看板及履历查询，全部在小程序内完成。
- **管理平台承担**：人员权限、全局基础资料、基础业务规则、既有服务接入配置、管理报表及导出、系统审计与运维。本文件不生成这些功能的手机页面。
- **待确认扩展**：P30–P32、P37–P39 以及 P29 远程关门、返航已移出本期。详见《中集待确认扩展功能清单》，不生成本期入口或不可用占位菜单。
- 设计稿备注区标注「标准版能力＋已确认端迁移」；待确认扩展保存在独立页面，不与正式流程相连。
- 物料商城、购物车、库存、支付、采购、多工厂切换仍不在本次界面范围。

## 2. 用户身份与界面权限

| 身份或关系 | 可以查看 | 可以操作 |
|---|---|---|
| 申请人 | 本人提交的订单、相关配送进度及有权限的消息 | 提交申请、申请取消、反馈未收货；若不是接收人，不默认可开门或确认取货 |
| 指定接收人 | 指定本人接收的订单及配送进度 | 身份验证并满足车辆条件后，扫码开门、确认本人对应订单取货、符合条件的继续出发 |
| 申请人同时为接收人 | 本人订单 | 同时拥有上述两类权限 |
| 仓库人员 | 所属仓库申请、批次、工单 | 受理、驳回、合单、装货、处理取消申请和工单 |
| 调度人员 | 被分配仓库的车辆、任务 | 人工选车、派单、监控、符合条件的开门、继续出发与停车取消 |
| 管理员／全厂查看权限人员 | 授权范围的全厂日常业务及记录 | 小程序查看业务概览；业务操作需对应授权。人员、权限和系统配置在管理平台完成 |
| 未准入或停用人员 | 准入提示 | 不进入业务页面 |

**同一人可以同时拥有多个角色，使用同一个内部账号，无需为不同角色分别注册或重新登录。** 例如一个人同时拥有工人、仓库人员和调度人员角色。原型应展示「仅申请人」和「指定接收人」两种订单详情。角色切换只改变工作区，不扩大数据权限。不要设计任意转授权、添加代取人或扫码即授权功能；当前基线以指定接收人为取货权限主体。

工人端不得展示同批其他工人的手机号或其他个人信息；仓库处理业务按授权范围显示必要资料。多人合单场景只需要展示「本站还有订单未取货」等汇总提示。

## 4. 各页面功能与交互

### P01–P02 登录、验证与准入

**页面内容**

- 系统名称「中集内部调度系统」，简短说明「工厂内部物料配送」。
- 「微信登录」「手机号验证码登录」两种入口，关联同一内部账号。
- 验证码方式包含手机号、验证码、「获取验证码」及「登录」按钮。
- 微信登录后，若手机号尚未验证或绑定，进入手机号验证步骤。
- 员工准入说明：「仅限已开通权限的内部员工使用」。

**交互与状态**

- 手机号格式错误、验证码错误或过期：字段旁提示，允许修改或重新获取。
- 发送限频：显示倒计时或稍后重试提示；具体秒数和错误次数按配置，不在设计中固定为业务规则。
- 微信授权取消、登录失败、网络失败：给出明确提示和重试入口。
- 非白名单：「当前账号未开通使用权限，请联系管理员」。
- 停用账号：「账号已停用，请联系管理员」。
- 登录过期：提示重新登录；不能继续下发车辆操作。
- 不设计开放注册、密码找回或自行选择管理员角色。

### P03 申请首页

**布局建议**：上方为系统标题与「扫一扫」快捷入口；主体为配送申请表单；底部为「提交申请」。保留清晰分组，避免将申请首页做成商城或复杂数据看板。

| 字段 | 控件建议 | 必填 | 提示与校验 |
|---|---|---|---|
| 货物名称及描述 | 多行文字输入 | 是 | 例如「维修用轴承 2 箱」；去除空白后不能为空 |
| 货物大小 | 文字输入 | 是 | 例如「每箱约 40 × 30 × 25 cm」；用于仓库人工判断装载，不自动计算 |
| 接收人 | 姓名输入 | 是 | 与指定接收关系相对应 |
| 接收人手机号 | 手机号输入 | 是 | 校验格式；实际取货需匹配已验证的内部账号 |
| 目的地 | 选择行，打开 P04 | 是 | 仅允许选择可用且已绑定的停靠点 |
| 预约时段 | 选择行，打开 P05 | 是 | 半小时一档，仅开放的未来时段 |
| 备注 | 多行文字输入 | 否 | 长度上限待确认 |

表单底部提示：「预约时段为申请配送计划，实际配送以仓库安排和车辆进度为准」。

接收人手机号未匹配内部账号时，允许保存申请信息，但展示「该接收人尚未完成账号绑定，暂无法扫码取货」。不把「账号未匹配」误设计成手机号格式错误，也不提供绕过身份校验的取货按钮。

点击提交先校验必填项，定位到错误字段。请求中按钮显示「提交中…」并防止重复点击；失败保留输入；成功进入 P06。下拉刷新更新可选点位及预约信息，建议保留已填写内容。

所属仓库由账号与业务配置确定，原文未要求工人自由切换仓库，不增加仓库选择器。

### P04 目的地选择

- 展示常用停靠点和当前可用停靠点列表，单选后确认。
- 使用停靠点名称作为主信息，可附已有位置说明，不新增地图选址。
- 未绑定、停用或不可达的点位不能作为目的地；可隐藏或禁用并说明原因。
- 无可用点位时提示「暂无可用停靠点，请联系管理员」，不允许手输地址替代。
- 常用地址实际是对已有停靠点的收藏，不是创建任意地址。

### P05 预约日期与时段选择

- 先选日期，再选半小时时段，例如「14:00–14:30」「14:30–15:00」。
- 区分可选、已选、已过期、未开放及容量已满状态。
- 仅允许选择开放的未来时段；日期范围、营业时间、容量取配置。
- 提交时若时段已不可用，提示重新选择，不清空其他表单内容。
- 没有可预约时段时给出空状态，不自行生成额外时段。

### P06 申请提交结果

- 标题「申请已提交」，状态「待受理」。
- 展示订单号、货物摘要、目的地、预约时段、接收人。
- 提示「仓库受理后可在订单中查看配送进度」。
- 操作：「查看订单」「返回申请首页」。
- 不显示「车辆已安排」「准时送达」等未经确认的信息。

### P07 我的订单

- 包含「我申请的」及「我接收的」订单，可用关系筛选区分，默认呈现有权查看的订单。
- 建议状态筛选为「全部」「待受理」「进行中」「待取货」「已结束」；进行中包含已受理、待发车、配送中，已结束包含已完成、已驳回、已取消。卡片始终显示准确业务状态。
- 卡片信息：订单号、准确状态、货物摘要、目的地、预约时段、本人关系；有车辆关联时显示车辆编号。
- 如有取消处理中、派发待核对或活动工单，使用附加标记，不替换订单主状态。
- 点击进入 P08；支持下拉刷新、分页加载、加载失败重试和无订单状态。

### P08 订单详情与配送进度

**从上到下的内容结构**

1. 订单状态卡：当前状态及简短说明；驳回时展示驳回原因；取消时展示实际处理结果。
2. 配送进度：待受理 → 已受理 → 待发车 → 配送中 → 待取货 → 已完成；驳回、取消为独立终止分支。仅显示实际产生的时间，不编造尚未发生的节点。
3. 车辆信息：有关联时显示车辆编号、当前任务目的地、订单收货点、在线情况、最新状态时间；必要时附数据过期提示。
4. 进度数据：距车辆下一停靠点的距离、当前路段参考耗时。下一停靠点与本单收货点分别标明，避免误导。
5. 申请信息：货物描述、大小、接收人及电话、目的地、预约时段、备注、申请人、提交时间、订单号；有批次时可展示关联批次号。
6. 操作记录：受理、驳回、发车、到达及本人订单取货等已发生事件。
7. 异常工单提示：展示关联活动工单状态和查看入口。
8. 底部操作区：按身份和状态展示可用操作。

**距离与耗时文案**

- 可以展示「距车辆下一停靠点 680 米」「当前路段参考耗时约 8 分钟」。
- 说明「参考耗时为历史路段估算，不是实时剩余时间」。
- 基础进度不能将路段参考耗时写成「8 分钟后到达」。本期不展示独立预计到达时刻或实时倒计时。
- 无数据使用「未知」或「—」，不能把未知显示为 0 米、0 分钟或正常。

**状态与按钮**

| 订单主状态 | 主要展示 | 操作规则 |
|---|---|---|
| 待受理 | 等待仓库处理 | 符合取消规则时显示「申请取消」 |
| 已受理 | 已受理，等待安排 | 未派发且符合规则时可申请取消 |
| 待发车 | 装货和批次已确认，等待发车 | 未派发且符合规则时可申请取消；任务规划中或结果待核对需额外提示 |
| 配送中 | 车辆配送进度 | 查看进度、按需求反馈未收货；不提供直接取消车辆任务 |
| 待取货 | 到达收货点，等待取货 | 仅授权接收人可「扫码取货」；申请人可查看但不默认可开门 |
| 已完成 | 本单已确认取货及确认时间 | 查询记录；有活动工单继续展示，不等于整车任务结束 |
| 已驳回 | 驳回原因和时间 | 查看详情 |
| 已取消 | 实际取消结果和时间 | 查看详情 |

有权查看订单的工人可进入未收货反馈；具体开放状态原文未限定，不额外编造禁用规则。重复反馈应优先打开已有活动工单。

### P09 取消申请确认与结果

- 入口主要面向未派发订单，最终由当前业务规则和权限决定。
- 确认提示：「提交取消申请后，由仓库处理。是否申请取消？」
- 提交后展示「取消申请已提交，等待仓库处理」，保留原业务状态。
- 仅收到实际取消结果后显示「已取消」。失败、超时或处理中不能显示取消成功。
- 已派发订单的取消处理方式待业务确认；原型可提示联系仓库，不提供一键取消整车任务。
- 工人申请取消的理由是否必填待确认；仓库处理界面见 P23。

### P10 扫码结果与可操作订单

- 「扫一扫」调用微信扫码能力，原型用扫描过渡画板和扫描结果模拟。
- 二维码用于识别车辆，不代表获得操作权限。
- 识别成功后展示车辆编号、当前停靠点、当前车辆状态及最新更新时间。
- 列出当前用户与该车辆、当前任务、停靠点匹配的可操作订单；多条订单逐条进入处理。
- 只有本人对应订单可确认取货，不提供「确认全车订单」按钮。
- 已取货的授权接收人仍可在满足条件时进入「继续出发」检查，不能只因本人订单完成就隐藏整个车辆操作入口。

**必须覆盖的扫码状态**

| 情况 | 提示／处理 |
|---|---|
| 无效或非本系统二维码 | 无法识别，请扫描车辆上的有效二维码 |
| 没有操作权限 | 当前账号无该车辆的取货操作权限 |
| 扫错车辆或任务不匹配 | 当前车辆没有与您匹配的可操作订单 |
| 车辆未到对应点位 | 车辆尚未到达本单收货点，暂不能开门 |
| 车辆或门状态未知／过期 | 状态待核对，请刷新或联系仓库 |
| 扫码取消 | 返回原页面，保留业务状态 |
| 相机权限不足 | 提示检查微信相机权限，允许返回 |

### P11 开门与确认取货

**页面内容**

- 当前订单、货物摘要、接收人、车辆编号、停靠点及本单对应格口。
- 明确显示格口，例如「取货格口：02 号」。格口未知时禁止开门，不允许打开全部箱门。
- 如为共享格口，提示「此格口内有其他订单货物，请仅领取本人货物」。不显示其他工人的个人信息。
- 分别呈现「开门请求结果」和「箱门当前状态」，避免混为一个成功状态。
- 按钮「打开取货格口」「确认已取货」及「未收到货」。

**交互步骤**

1. 授权接收人点击打开格口，请求中防止重复点击。
2. 请求被受理后显示「开门请求已提交，正在核对箱门状态」。
3. 收到有效门状态后显示「箱门已打开」；失败明确提示；超时或没有反馈显示「状态待核对」，不直接宣称门已开。
4. 用户实际取走货物后点击「确认已取货」，弹窗提示「请确认您已取走本订单货物；确认后本订单将完成」。
5. 确认成功只完成选中的本人订单，显示确认时间；同批其他订单保持各自状态。
6. 提示「请按现场操作方式关闭箱门」。本期采用现场关门，不提供远程关门入口。

箱门已打开不自动确认取货，扫码成功不自动完成订单。控制请求超时后提示核对状态，避免引导用户连续重试。

### P12 继续出发条件与确认

此功能由扫码车辆后进入，表示前往当前车辆任务的下一停靠点。标题和按钮统一使用「继续出发」，不能把这个操作改名为「返航」。返航控制不属于本期。

**页面展示**

- 车辆编号、当前停靠点、明确可识别的下一停靠点。
- 条件检查结果：通过、未满足或待核对；使用文字和图标，不只靠颜色。
- 当前状态更新时间及刷新入口。

| 检查项 | 可操作要求 | 不满足时的文案示例 |
|---|---|---|
| 身份与当前位置 | 用户有当前车辆及订单操作权限，车辆在当前任务对应点位 | 当前账号无操作权限／车辆不在对应停靠点 |
| 本站取货 | 本站全部相关订单已确认取货 | 本站还有订单未完成取货 |
| 异常工单 | 没有未处理的相关异常工单 | 存在待处理异常，请联系仓库 |
| 箱门 | 相关箱门最新状态全部关闭 | 箱门未关闭，请按现场方式关门 |
| 数据有效性 | 车辆任务和门状态未过期 | 状态待核对，请刷新或联系仓库 |
| 下一停靠点 | 当前任务存在且能明确识别下一目标 | 当前为末站／下一停靠点待核对 |
| 请求互斥 | 没有其他待确认的离开请求 | 已有出发请求待确认，请勿重复操作 |

仅全部满足时启用「确认继续出发」。任一条件不满足时说明原因并提示联系仓库；原文未提供仓库联系电话，不虚构一键拨号能力。

末站或下一停靠点不明确时，不提供可执行的离开按钮，显示原因即可。

确认弹窗：「确认让车辆前往下一停靠点『装配二区取货点』？请确认人员已远离车辆。」下一点名称来自当前任务；示例文案中的名称为演示数据。

提交后先显示「出发请求已提交，等待车辆状态确认」；只有实际有效车辆状态更新后才显示「车辆已继续出发」。请求失败与结果未知分别呈现，不把按钮点击或接口受理等同于车辆已行驶。

本站多人取货场景要提供一个变体：本人已取货，但他人未取货，继续出发不可用。本人已完成记录保留，不回退为待取货。

### P13 未收货反馈

- 展示关联订单号、货物摘要和目的地；已有关联批次时保留关联，不要求用户手工输入批次。
- 文字说明输入框，用于描述未收货情况；不新增图片上传、视频或附件功能。
- 「提交反馈」按钮，请求中防重复提交；说明长度等参数待确认。
- 同一订单已有活动工单时，优先提示并打开原工单，避免再次创建。
- 提交成功显示工单号、状态「待处理」，说明「仓库将介入核对，请在工单中查看处理进度」。
- 按钮「查看工单」「返回订单」。反馈不会自动改变订单状态或触发重新配送。

### P14–P15 我的异常工单与详情

**列表**：展示本人提交工单的工单号、关联订单、说明摘要、提交时间、状态。可按「全部／待处理／处理中／已关闭」筛选，支持分页与空状态。

**详情**：展示工单状态、关联订单、提交内容和时间；受理后展示处理人、受理时间；关闭后展示处理结果及关闭时间。用时间线呈现提交、受理、处理与关闭记录。

工人只查看自己的工单进度与结果；仓库角色进入 P33 处理、填写结果并关闭工单。记录至少在线保留 31 天，不把 31 天设计成强制查询上限或到期立即消失。

工单「已关闭」只表示处理流程关闭，不能自动显示订单已完成、车辆已取消或已再次派车。

### P16–P17 消息列表与详情

- 消息类型：受理、驳回、发车、到达、取消、异常处理。
- 列表卡片：标题、摘要、时间、未读标记；只展示当前用户有权限的消息。
- 详情展示消息正文、时间和「查看订单」或「查看工单」入口。
- 站内消息页面打开时查询或刷新，可提供下拉刷新。
- 未读标记及进入详情后的已读效果需一致。
- 覆盖暂无消息、加载失败和关联记录无权限／不可用状态。
- 短信仅用于登录验证码，本期不生成短信到货提醒、微信订阅或通知偏好入口。

### P18 个人中心

- 展示当前身份信息：姓名或已有昵称、已验证手机号、全部已授权角色标签，以及各角色对应的仓库／数据范围；标明当前工作区。

### P19 常用停靠点管理

- 列表显示已收藏停靠点及可用状态。
- 「添加常用停靠点」从已有可用点位中选择；支持移除收藏并确认。

- 添加／移除收藏是实现「常用地址」的建议交互，原文未规定默认地址、排序和数量限制，不做强制规则。

### P20 九识小程序入口

- 在已有车辆相关页面展示「打开九识小程序」，默认只对仓库、调度和管理员角色可见，普通工人隐藏。
- 普通首页跳转作为通用入口，车辆管理及移动仓库工作台使用本期既有业务页面。
- 跳转前可说明「将打开九识小程序首页，可能需要在目标小程序中登录」。

- 此处仅为普通首页跳转，不提供免登录、指定车辆直达或完整功能复刻。

### P21 角色工作区切换

- 展示同一账号已获授权的工人、仓库、调度和业务概览工作区，卡片显示角色名称、对应仓库／数据范围，勾选当前工作区。仅展示已授权项，工作区切换使用单选，不是修改账号的多角色授权。
- 无需退出登录即可切换首页、导航和当前业务视角；未提交表单先提示继续编辑或放弃后切换，不默认新增草稿保存能力。切换后刷新列表和按钮，不能保留上一角色的越权数据。
- 只有一个工作区时直接进入首页，可不显示切换入口；多个工作区时默认使用上次仍有权限的工作区，首次进入提供选择。权限撤销后刷新并退出失效工作区，重新选择其他有效工作区；无可用工作区时显示无权限状态。
- 权限按「角色、具体操作、该角色对应数据范围」成组校验。角色可以并存，但不能把一个角色的操作能力与另一个角色的更大数据范围随意组合；同一账号的工人身份仍按本人申请／接收关系展示。
- 业务操作记录同一真实账号、当次业务角色、仓库／对象、时间与结果。多角色不代表获得代取权限，管理员也不能绕过车辆条件。
- 消息按账号聚合可见业务消息，同一事件不因拥有多个角色而重复显示；点击消息时，如需切换到另一个已授权工作区，先明确提示并处理未提交表单，然后打开目标。未读数量基于去重消息。
- 管理员身份不直接获得车辆控制特权，控制仍需对应权限及有效现场状态。

### P22 仓库工作台与申请列表

- 顶部显示所属仓库，统计待受理、待装货、待发车、待处理异常数量，点击进入对应列表。

- 点击处理进入 P23；批量勾选已受理申请后进入 P24。排序只是查看顺序，不等同于自动派单。
- 覆盖空列表、刷新、分页、多选退出及订单被他人处理后的刷新提示。

### P23 申请审批与取消处理

- 完整显示申请字段、当前状态和处理历史，底部提供「受理」「驳回」。驳回必须填写原因。
- 受理成功后可选择「加入配送批次」或返回列表，记录操作者和时间。
- 有取消申请时提供处理入口；未派发订单若在批次内，先移出批次并重新确认装货，再完成取消。
- 已派发单个订单的取消转人工核对，不自动取消整车任务；展示关联批次影响。
- 覆盖处理中、他人已处理、状态变化、失败及结果待核对。

### P24 合单与批次编辑

- 批次列表显示批次号、停靠点、预约时段、订单数量、车辆和批次进展。

- 校验同仓库、同停靠点、同预约时段；不符合的订单不可勾选并说明原因。
- 批次详情展示成员订单与独立取货状态，可在发车前移出订单；变更成员后重新确认装货。
- 任务请求已下发或结果未知时锁定编辑，不能拆批重派。合单不覆盖原订单号、接收人及记录。

### P25 装货与格口分配

- 展示货物清单、文字大小、目标车辆和实际可用格口；车辆可在本步骤选定，也可跳转 P26 选车后返回。
- 仓库人工确认装载能力，为每单绑定明确格口，记录装货人和时间；未知格口不能提交。
- 共享格口显示共同取货提示；需要隔离时使用独立格口，超容量提示拆批。
- 提供「打开装货格口」「确认装货完成」，只操作授权格口；请求结果和门状态分开显示。
- 重新选车后必须重新校验格口和装载；未确认装货不能直接派单。

### P26 选车与派单确认

- 车辆卡片按空闲／使用中分类，显示在线情况、电量、位置、当前任务及状态时间。
- 离线、数据过期、非空闲或已有任务的车辆不可作为新任务车辆，展示原因。
- 确认页汇总车辆、批次、订单数、格口、目的地、预约时段和装货确认；「确认派车」二次确认。
- 提交前重新校验；处理中防重复。接口受理后显示任务规划中，有效行驶状态到达后显示配送中。
- 超时显示「派发待核对」，提供查询当前任务入口，不提供盲目重发。重新派单必须保留原任务关联记录。

### P27 调度台与任务详情

- 首页展示待派发批次、执行中任务、待核对请求和系统异常入口。
- 任务卡片展示车辆、批次、当前停靠点、下一点、业务进展和异常标记。
- 详情展示目标点序列、关联订单各自状态、格口、任务时间线、控制请求和实际状态反馈。
- 提供选车派单、车辆详情、执行记录、取消任务入口；各按钮按权限和状态启用。
- 连接异常、车辆离线和数据过期分别呈现；调度人员核对现场与本地记录差异并填写处理说明，不伪造成功状态。

### P28 车辆列表与详情

- 列表按车辆编号搜索，筛选空闲／使用中、在线／离线，显示电量与最新状态时间。
- 详情包含位置、速度、当前任务、目的地、格口及箱门状态、关联批次、当前异常。
- 提供「车辆控制」「业务记录」「打开九识小程序」入口；工人只能查看与本人订单相关的信息及原有授权操作。
- 无任务、数据未知、离线、状态过期使用独立变体，不以缺失值推断空闲或箱门关闭。

### P29 车辆控制与任务取消

操作按权限分组，每个动作均有确认、请求中、成功反馈、失败和结果未知状态；动作受理与现场执行结果分别显示。

| 操作 | 界面与条件 |
|---|---|
| 打开格口 | 选择明确且有权限的格口，校验任务和现场条件；不默认打开全部箱门 |
| 继续出发 | 使用 P12 条件，前往当前任务下一停靠点 |
| 取消车辆任务 | 车辆无速度且符合接口条件；确认弹窗列出受影响批次和订单，说明取消后车辆停在原地；订单后续处理另行记录 |

本期不提供远程关门或返航控制。现场关门及车辆已有任务状态展示不受影响。

### P33 仓库异常工单处理

- 按所属仓库显示待处理／处理中／已关闭工单，支持按时间、订单、处理人筛选。

### P34 日常业务概览与统计

## 5. 全局状态与组件

### 通用组件

导航栏、底部 Tab、必填输入项、单选列表、日期与时段选择器、订单卡、状态标签、进度时间线、车辆状态卡、格口状态卡、条件检查行、底部操作栏、确认弹窗、轻提示、空状态、加载骨架和失败重试块。

### 必须一致的状态语义

| 状态类别 | 设计要求 |
|---|---|
| 加载中 | 展示加载状态；提交和车辆控制按钮防重复点击 |
| 空内容 | 说明没有订单、消息、工单或可用点位，给出适当返回或新增入口 |
| 请求失败 | 明确失败原因或通用失败提示；普通查询可重试 |
| 请求结果未知 | 使用「待核对」，不显示确定成功；车辆控制不引导盲目重发 |
| 数据未知 | 显示未知或占位符，不能用零、关闭或在线替代 |
| 数据过期 | 显示更新时间和过期提示；不能据此允许开门或继续出发 |
| 车辆离线 | 独立说明车辆状态；不要与服务连接异常混为同一状态 |
| 无操作权限 | 隐藏不适用入口；扫码误入等场景提供原因及返回 |
| 订单与工单并存 | 订单保留原主状态，工单作为独立状态展示 |

提示应说明当前发生了什么及下一步如何处理；不要把技术错误码直接作为工人端文案。所有不可操作按钮旁必须能找到原因，避免只显示灰色按钮。

## 6. 需要连通的原型流程

### 流程 A：提交申请与查看进度

登录 → 验证手机号／准入 → 申请首页填写 → 选择停靠点 → 选择预约时段 → 提交成功 → 订单详情待受理 → 已受理 → 待发车 → 配送中 → 待取货。

分支：必填缺失、接收人未绑定、时段不可用、提交失败、申请驳回及查看原因。

### 流程 B：取货并完成本单

待取货订单 → 扫一扫 → 识别车辆并校验 → 选择本人可操作订单 → 打开对应格口 → 展示请求与门状态 → 用户实际取货 → 确认已取货 → 本单已完成。

分支：仅申请人无取货权限、扫错车辆、共享格口、门状态待核对、未收到货。

### 流程 C：扫码继续出发

扫码车辆 → 本人具备权限 → 查看本站取货／异常／箱门／数据／下一点检查 → 全部满足 → 二次确认 → 请求已提交 → 实际状态更新为继续行驶。

阻断变体：其他订单未取、存在活动工单、门未关、状态过期、有待确认请求、末站无下一点。

### 流程 D：未收货反馈闭环

订单详情 → 未收到货 → 填写说明 → 提交成功 → 工单待处理 → 处理中 → 已关闭并查看结果。消息中的异常处理通知可跳转到同一工单。

分支：已有活动工单时进入原工单。关闭工单后不自动改变订单或车辆状态。

### 流程 E：取消申请

未派发订单 → 申请取消 → 确认提交 → 显示取消处理中并保留订单状态 → 仓库实际处理后显示结果。

### 流程 F：其他入口

个人中心 → 常用停靠点 → 添加／移除；消息列表 → 消息详情 → 对应订单／工单；有权限角色车辆页 → 九识小程序首页 → 返回后刷新车辆状态。

### 流程 G：仓库与调度协作（含同一人多角色）

同一账号选择已授权的仓库工作区 → 受理申请 → 同点同时段合单 → 选车并分配格口 → 确认装货 → 切换到已授权调度工作区 → 确认派车 → 规划中 → 配送中 → 到达 → 工人各自取货。覆盖审批驳回、取消申请处理、车辆不可用、格口不匹配和派发待核对。

### 流程 H：车辆控制

车辆详情 → 开门／继续出发／停车取消 → 校验权限、任务、格口和现场条件 → 二次确认 → 请求反馈 → 实际状态更新。覆盖条件不满足、失败、结果未知和转人工核对。

流程 I（原地图、预测与外部通知）已移至待确认扩展，不连接本期业务。

### 流程 J：业务概览与工单处理

业务概览 → 当日指标／业务日期筛选 → 订单、任务或工单明细 → 处理履历。仓库工单列表 → 受理 → 调查并填写说明 → 填写结果关闭 → 工人收到消息查看结果。以上全部在小程序内完成，管理平台不提供重复处理入口。

## 7. 原型示例数据

以下均为虚构演示数据，仅用于填充界面；时间必须相对演示场景保持为有效未来时段。

| 项目 | 示例 |

| 手机号展示 | 138****2468；输入表单用「请输入手机号」占位 |
| 所属仓库 | 一车间物料仓 |

| 下一停靠点 | 装配二区取货点 |
| 预约时段 | 演示日期的下一日 14:00–14:30 |
| 订单号 | DD-20260919-0012 |

## 8. 待业务确认事项

以下事项不妨碍先生成界面，但不能由 AI 擅自确定为最终规则：

1. 员工白名单与接收人账号绑定细节；是否最终保持「指定接收人可取货、仅申请人不可取货」的基线。
2. 营业时间、开放预约日期范围、每时段容量及文字长度上限。
3. 取消申请的可用条件、派发后处理方式、是否需要取消理由。
4. 是否接受共享格口；不接受时原型按独立格口展示。
5. 车辆与门状态的新鲜度阈值、未取货超时阈值。
6. 工单处理责任人与联系仓库的实际方式。
7. 常用停靠点默认项、数量限制等细节；当前仅建议添加和移除收藏。
8. 九识入口在多角色小程序账号中的具体展示位置。
9. 品牌视觉规范、姓名／手机号展示与脱敏细节。
10. 已要求的日常业务移动端调整需同步正式需求基线；现阶段仅做标准版功能，额外能力不设计、不开发、不计入本期验收。

- [ ] 32 项小程序业务页面／弹层清单均有对应画板或明确合并位置。
