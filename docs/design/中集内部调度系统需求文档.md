# 中集内部调度系统需求文档

标准版产品需求说明

版本：V1.0　日期：2026年9月18日　状态：待业务确认

本文用于中集工厂内部物料配送小程序及管理后台的设计、开发与验收。系统覆盖工人申请、仓库受理与人工合单、车辆派发、扫码取货、符合条件的扫码继续出发、未收货异常工单及记录查询。

依据原需求模板、补充说明、九识开放API V2.9、MQTT推送V2.9及功能范围与报价V1.3编制。需求以当前标准版范围为基准；界面细节和未确定的配置值在原型及联调阶段确认，不预设厂商未公开的能力。

## 一 项目目标与范围

项目服务单工厂、初期1～10台无人车。工人通过微信小程序提交文字物料需求；仓库与调度人员使用PC后台受理、装货和派单；管理员查看本工厂全部业务记录。软件由开发方自行开发、测试、联调和维护。

系统提供24个模块：登录与身份、配送申请、常用地址、我的订单、配送进度信息、扫码取货、扫码车辆离开、站内消息、仓库工作台、人工合单配送、任务调度、车辆监控、基础资料、角色权限、异常处理、未收货异常工单、订单与任务关联、状态接入、控制可靠性、操作日志与记录留存、基础统计、运行维护基础、九识小程序入口、项目交付。

主流程为：工人申请 → 仓库受理 → 同站同时间段人工合单或单独配送 → 装货确认 → 人工派车 → 到达 → 扫码开门 → 用户确认取货 → 自有配送订单完成。

车辆任务继续独立运行。当前站全部相关订单已取、箱门关闭且任务存在下一停靠点时，可扫码确认继续出发。业务订单完成不等于车辆任务结束。

### 范围边界

- 物料采用文字描述，不建设物料库、物料编码、库存和采购管理。
- 合单限同仓库、同停靠点、同预约时段，装载能力由仓库判断。
- 目的地从车辆可达且已绑定的停靠点中选择。
- 配送进度展示剩余距离和历史路段参考耗时，不提供精确实时到达时刻。
- 车辆控制限现有接口支持的任务派发、指定格口开门、继续出发和停车状态下取消任务；不包含远程关门或自动返航控制。
- 九识小程序提供普通首页跳转入口，不复制其APP全部功能，不实现免登录或指定车辆直达。
- 仓库手机工作台、多工厂、智能调度、轨迹回放和其他系统对接不属于本版。

## 二 用户角色与页面

角色控制既约束页面按钮，也约束后台接口和数据查询。管理员可查询全部记录，不默认获得绕过车辆操作条件的权限。

| 角色 | 数据范围 | 主要操作 |
|---|---|---|
| 工人 | 本人申请或被指定接收的订单 | 申请、查进度、申请取消、授权取货、反馈未收货 |
| 仓库人员 | 所属仓库的申请、批次和工单 | 受理、驳回、装货、合单、处理工单 |
| 调度人员 | 被分配仓库的车辆及任务 | 选车、派单、开门、符合条件的继续出发和取消 |
| 管理员 | 本工厂全部业务及操作记录 | 人员启停用、角色分配、基础配置、查询及导出 |

同一人员可拥有多个角色。申请人可查看订单，但开门及确认取货权限默认授予指定接收人；申请人与接收人相同时自然拥有取货权限。此规则为本版设计基准，业务方确认后冻结。

### 工人小程序页面

- 登录页：微信登录、手机号验证码登录、员工准入提示。
- 申请首页：货物文字、接收人、电话、目的地、预约时段与备注。
- 我的订单及详情：审批结果、订单进度、批次关联车辆、当前目的地、取货及异常入口。
- 扫码操作页：识别车辆、匹配本人可操作订单、开门、确认取货及符合条件的继续出发。
- 异常工单及消息页：提交反馈、查看处理结果和站内消息。
- 个人中心：身份信息、常用停靠点和退出登录。

### 仓库及管理员页面

后台包含申请列表、申请详情、批次编辑、装货与发车、车辆详情、异常工单、记录报表、人员权限与基础配置。申请列表纵向排列；仓库受理后可进入发车界面查看空闲和使用中的车辆。

仓库列表默认按预约时间、申请提交时间排序，支持状态、日期和人员筛选。列表查看顺序与派车操作分开，人工选择合单时保留操作记录。

## 三 登录申请与订单

### 登录与员工准入

支持微信登录及手机号验证码登录，两种登录方式关联同一内部用户。手机号经过验证后才能建立或修改绑定，不能仅凭前端提交的号码合并账号。停用账号不得访问业务接口。员工白名单、所属仓库及角色由管理员维护。

微信首次绑定使用管理员开通的内部账号和密码；账号必须已完成首次改密且处于启用状态，未匹配账号时不能获得业务操作权限。

### 配送申请字段

| 字段 | 要求 | 校验规则 |
|---|---|---|
| 货物名称及描述 | 必填文字 | 去除空白后不能为空 |
| 货物大小 | 必填文字 | 仓库据此人工评估装载 |
| 接收人及手机号 | 必填 | 校验号码格式，取货时核对已验证身份 |
| 目的地 | 必填停靠点 | 从可用点位选择，不接受自由地址作为任务目标 |
| 预约时段 | 必填 | 半小时一档，只选开放的未来时段 |
| 备注 | 选填文字 | 长度上限在原型阶段确认 |

提交后生成唯一订单号并记录申请人、接收人、所属仓库和提交时间。重复点击不得生成重复订单。营业时间及每时段容量可配置，预约表示申请计划，不构成准时送达保证。

### 订单状态

建议业务状态为待受理、已受理、待发车、配送中、待取货、已完成、已驳回、已取消。派发请求结果不明时保留原业务状态并增加“派发待核对”标记，不直接标记配送中。

仓库受理或驳回时记录人员与时间，驳回必须填写原因。待发车由装货和批次确认触发；配送中、待取货由匹配任务与停靠点的有效车辆状态更新；已完成仅由授权用户确认取货触发。异常工单单独维护，不用“异常”覆盖订单原状态。

未派发订单的取消申请由仓库处理；已入批次订单先移出批次。派发后的单个订单取消不得自动取消整车任务。已完成记录不得被管理员无痕修改，纠正需保留原值、原因和操作记录。

## 四 合单装货与派车

### 人工合单

仓库勾选多条已受理且未被其他活动批次占用的订单，系统校验仓库、停靠点和预约时段一致后生成批次。单条订单也可形成配送批次。发车前可移出订单并重新确认装货；请求已下发或结果待核对时锁定批次，禁止直接拆批重派。

一个批次关联多条自有订单、一台车辆及一次九识任务。各订单展示同一车辆进度，但分别保留接收人、格口和取货记录。自有订单管理不依赖九识orderList推送。

### 格口与装载

仓库人工确认货物可装载，选择实际车辆支持的格口并记录订单与格口关系。共享格口需接受共同取货：开门会暴露格口内全部货物。要求物理隔离时按独立格口分配，超过格口或装载能力必须拆批。系统不根据文字大小自动计算装载量。

开门仅传入已授权订单或装货任务对应的格口编号。格口不明确时禁止下发，不能利用接口空格口参数打开全部箱门。

### 发车与任务跟踪

发车页面展示车辆空闲/使用中、在线状态、电量、当前位置与数据时间。提交前重新核对车辆、当前任务和目的地点位绑定。只有车辆在线、状态数据有效、空闲且无当前任务时才允许本系统创建新任务；最终受理以九识接口结果为准。

使用普通任务接口创建任务并出发，保存返回的dispatchId及请求记录。任务规划中只显示规划中，收到匹配任务的行驶状态后再标记配送中。到达判断需同时匹配车辆、任务、当前目的地和ATSTOP状态，不能只凭车辆位置判断取货状态。

对同车派发实行本地并发锁和业务防重。接口超时后进入待核对状态，通过车辆详情查询当前任务；无法明确归属时转人工，不盲目自动重发。重新派单保存新的任务关联及原记录。

取消车辆任务仅在车辆无速度且符合接口条件时发起，取消后车辆停在原地。单个订单取消与整车任务取消分别处理，明确失败或超时不能显示取消成功。

## 五 扫码取货与继续出发

### 扫码及开门

二维码由自有系统管理，用于识别车辆或业务入口，不作为授权凭证。后台根据登录人、订单接收关系、车辆当前任务、停靠点和格口判断是否可操作，扫描其他车辆不能取得其控制权限。

授权接收人在车辆到达对应点位后可请求打开订单对应格口。接口调用结果和MQTT的doorStatus分别展示；未收到有效反馈时显示状态待核对。用户确认已取货后，系统只完成该用户对应订单，并记录确认人员和时间，不自动完成同批其他订单。

### 扫码继续出发

用户扫码后明确确认让车辆离开，后台须同时满足以下条件才调用go：

1. 用户有当前车辆及订单操作权限，车辆处于当前任务的对应停靠点。
2. 当前站全部相关订单已确认取货，没有未处理的相关异常工单。
3. 相关箱门最新状态全部为关闭，车辆任务及门状态未过期。
4. 根据当前任务目标列表及目标序号能够明确识别下一停靠点。
5. 当前没有其他待确认的离开请求。

有任一条件不满足时，页面说明原因并提示联系仓库。任务已到末站或下一目标不明确时不提供离开操作。go只代表前往任务下一停靠点，不作为返航接口。重复点击不重复下发；调用后显示请求结果，再通过有效车辆状态更新实际行驶进度。

上述校验只约束本系统下发指令。九识平台或车辆自身的离站策略需实车核对；本系统不能仅靠限制按钮保证车辆始终停留等待。取货后的箱门关闭按车辆现场操作方式完成，本系统读取门状态。

### 并发和异常

多人同站取货时，第一个用户完成取货不能直接放行整车。共享格口内订单仍分别确认。反馈未收货、接口超时、门状态缺失或车辆状态变化时，保留已完成的取货记录，并将后续车辆操作交由仓库核对。

## 六 异常工单消息与第三方入口

### 未收货异常工单

工人可在自己有权查看的订单中提交文字反馈。系统记录工单号、关联订单及批次、提交人、说明和时间，并在所属仓库后台显示异常标记。重复点击不得重复建单；同一订单已有活动工单时优先引导查看原工单。

工单状态为待处理、处理中、已关闭。仓库受理时记录处理人和受理时间，关闭时必须填写处理结果。工人可查看自己工单的进度及结果，管理员可查看全部。处理记录在线保留至少31天。

关闭工单不自动触发确认取货、取消任务或再次派车。需要后续配送时由仓库按正常申请和派发流程处理并记录原因，避免把业务调查结果误当作车辆动作成功。

### 系统异常

后台展示接口明确失败、派发结果未知、MQTT连接异常、车辆数据过期和取货超时。连接异常与车辆离线分别显示；数据过期不得继续作为开门或离开的依据。每个异常记录发生时间、关联车辆或任务、处理人及处理说明。

### 站内消息

系统根据受理、驳回、发车、到达、取消及异常处理生成站内消息，提供未读标记和详情入口。消息仅展示给有权限的用户，页面打开时查询或刷新。此版不承诺短信业务通知、微信订阅消息或后台实时送达提醒。

### 九识小程序入口

在车辆相关页面提供打开九识小程序的按钮。使用客户提供的有效AppID，通过微信普通跳转能力打开首页，处理用户取消、目标不可用和打开失败提示。入口访问角色默认限仓库、调度和管理员。

不传递业务密钥，不承诺共享登录或直达指定车辆。目标端功能由九识提供，截图中的APP能力不作为本系统交付要求。返回本系统后刷新能从API/MQTT获得的车辆状态，不据此自动确认取货或完成工单。

## 七 车辆接口与状态接入

小程序和PC后台只调用自有服务端。九识密钥和token保存在服务端，按返回有效期管理，业务日志中脱敏。接口地址以完整原始文档及对接配置为准，现有转换文档中的断行地址不得直接复制上线。

| 能力 | 文档依据 | 使用规则 |
|---|---|---|
| 鉴权 | API第1节 | 获取并维护token |
| 基础资料与车辆详情 | API第3至6节 | 同步站点、点位、车辆和格口；车辆详情每车每秒最多一次 |
| 派发普通任务 | API第7节 | 传车辆及目标点，保存dispatchId |
| 取消任务 | API第10节 | 无速度时调用，结果未知转核对 |
| 继续出发 | API第11节 | 在停靠点前往任务下一个点 |
| 打开格口 | API第12节 | 明确传vehicleName和gridNos |
| 实时状态 | MQTT第2节 | 车辆开机联网时1Hz推送 |
| 业务状态 | MQTT第3节 | 状态变化时推送，关联目标点和任务 |

### 状态展示

车辆实时快照包括在线情况、电量、位置、速度、配送状态、箱门状态、当前任务和上报时间。业务推送补充currentStopId/currentStopName及路段信息。无值显示未知，不把空值当作零或正常状态。

配送进度展示currentToTargetMileage及currPlanElapsedTime；前者为距下一停靠点的米数，后者为历史数据推算的整段参考分钟数。页面明确标注参考耗时，不将其当作实时剩余时间。

### 接收与恢复

按车辆和任务隔离消息，利用timestamp避免旧数据覆盖新状态。无法唯一判序的冲突状态进入核对；消息处理和订单更新需支持重复执行而不重复产生业务动作。

MQTT断线后重连并查询当前车辆详情，其余字段等待新消息。仅记录实际收到的历史事件，不承诺断线期间完整补发。与九识平台发生人工操作冲突时，保留现场状态与本地业务差异，交由调度核对。

## 八 数据安全与运行要求

### 核心数据关系

| 数据对象 | 关键内容 |
|---|---|
| 用户与角色 | 内部ID、验证手机号、微信身份、角色、仓库、启停状态 |
| 配送订单 | 订单号、申请人、接收人、货物文字、点位、时段、状态 |
| 配送批次 | 批次号、成员订单、车辆、格口、目的地、装货及派发状态 |
| 任务记录 | vehicleName、dispatchId、目标序列、请求结果、核对状态 |
| 车辆快照 | 来源、任务、位置、门状态、业务状态、上报及接收时间 |
| 工单与日志 | 关联订单、处理记录、操作者、请求及状态变化时间 |

dispatchId以不会丢失Long精度的形式贯穿存储和前后端传输。订单、批次与任务采用独立标识，不用手机号或车牌作为唯一业务主键。

### 留存与权限

申请处理、批次派发、取货、工单及操作日志至少在线保留31天。本版建议自订单/工单关闭或最后一次处理起计，未完成记录继续保留；该计时口径待业务确认。逐秒原始遥测可采用单独策略，不能删除业务审计所需事件。

所有列表、详情、导出与控制请求在后台校验数据归属。工人不能读取同批他人的手机号，停用用户立即失去访问权限。关键记录修正留痕，凭证和验证码不进入普通日志。导出记录操作者、筛选条件和时间。

### 性能与运维

原需求的首屏加载目标为小于3秒。建议验收口径为约定设备和正常网络下，从打开页面到首屏主要业务内容可操作；是否包含首次下载、样本数及负载水平在验收前确认。列表分页加载，不因大量记录阻塞操作。

车辆最新状态显示上报时间，数据新鲜度阈值可配置，具体值经联调确认。门状态未知或过期时不得放行控制。API限流、MQTT连接、错误率和数据库备份设监控；备份频率、保存周期和恢复目标在部署方案中确定并进行恢复验证。

本版支持单工厂1～10台车；并发用户、日订单量和可用性目标需按客户实际规模确定，不承诺未约定的高可用等级或24小时人工值守。

## 九 验收标准

验收以本版范围和双方确认的原型为准，使用有权限的测试账号、实际车辆和已绑定停靠点。以下各组用例需保留执行结果；外部依赖未就绪时记录阻塞原因，不将模拟结果作为车辆动作已通过。

| 编号 | 验收场景 | 通过条件 |
|---|---|---|

## 十 实施依赖与交付

### 开发前准备

客户提供微信小程序主体及相关权限、员工及仓库划分、云资源账户、九识appId/appKey、MQTT接入配置与organizationCode、车辆及已绑定点位、目标九识小程序AppID和测试账号。九识协助提供完整接口资料、实际字段样例及现场车辆配合。

### 需要业务确认的配置

- 员工白名单、接收人账号绑定和各仓库人员归属。
- 营业时段、预约容量、文字长度、取消申请处理规则。
- 合单共享格口是否接受；不接受时按独立格口限制容量。
- 订单及工单留存起算点、导出范围和备份保留规则。
- 未取货超时阈值、数据新鲜度阈值及未收货工单处理责任人。
- 首屏性能的测试设备、网络、样本量及实际业务负载。

这些事项用于配置和验收口径，不新增未开放的车辆能力。厂商车辆状态、停留策略与现场流程不一致时，由客户和九识共同确认可执行的现场安排。

### 交付清单

交付小程序、PC后台及后端源代码，数据库结构说明，部署脚本或部署说明，配置清单，九识对接说明，测试与验收记录，操作手册及一次培训。账号归属和源码权属按合同约定。

本需求文档不记录开发方内部成本或谈判底价。标准版开发报价、维护费、付款安排和保修条款见《中集内部调度系统功能范围与报价》V1.3；标准版开发报价为128,000～158,000元，最终合同金额在该区间内确认；年度维护报价仍为2.4万元，验收后提供3个月免费缺陷保修。本次报价调整不改变功能范围。

### 版本依据

原需求模板明确内部物料配送与半小时预约；补充说明明确人工合单、未收货反馈、至少一个月记录留存和分角色查询。API第1、3至7、10至12节支持本版车辆接入；MQTT第2、3节支持状态与路段信息。微信普通小程序跳转采用wx.navigateToMiniProgram。
