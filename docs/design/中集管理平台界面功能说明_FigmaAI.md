# 中集内部调度系统｜管理平台界面功能说明

> 当前执行范围（2026-09-19）：现阶段只做标准版功能，其他不做。额外能力仅留档，不作为待执行任务。已要求的日常业务迁移小程序继续保留。

用途：可直接交给 Figma AI 生成桌面管理平台页面和可点击原型。  
版本：V1.2（本期范围收敛，支持一人多角色）；日期：2026-09-19。  
依据：《中集系统功能端划分建议》V2.2、《中集小程序界面功能说明_FigmaAI》V3.2、《中集内部调度系统需求文档》V1.0。

范围原则：**日常业务全部在小程序，管理平台只负责管理、配置、统计、审计和运行支撑。** 本文可独立使用，不需要 Figma AI 读取其他文件才能理解页面范围。布局、控件、页面拆分及演示数据属于原型设计建议；未确定参数按业务确认值实现。额外能力移入《中集待确认扩展功能清单》，不生成本期入口。

## 1. 可直接给 Figma AI 的生成指令

请设计「中集内部调度系统管理平台」，用于单工厂、初期 1～10 台无人车的系统管理。目标用户是具有相应权限的系统管理员、管理报表查看人员及运维人员；这些是权限视角，不要求新增三个固定系统角色。

生成中文桌面 Web 高保真原型，以 1440 × 900 为主画板，兼顾 1280 像素宽度。采用固定左侧导航、顶部栏、面包屑和内容区，使用清晰的表格、筛选区、详情抽屉、分组表单、状态标签和确认弹窗。视觉建议浅灰页面底色、白色内容卡、蓝色主操作，成功／提醒／错误有图标和文字配合。使用中性企业风格，不虚构中集官方 Logo，不做面向车队调度的大屏。

默认进入有权限的员工管理、基础资料或报表页；管理报表展示基础汇总。不要把待审批订单、待发车车辆或待处理业务工单作为首页操作入口。

必须生成下文 M01–M04、M06–M08 七个本期页面组中的具体画板及关键状态，连接核心管理流程。表格不能只有装饰性数据；筛选、查看、编辑、确认、成功／失败反馈应形成完整原型链路。业务记录可只读下钻，界面用明显的「只读」标识区分。

**禁止生成的日常业务按钮**：提交申请、受理／驳回、合单、订单格口分配、装货、人工派车、停车取消、开门、继续出发、确认取货、业务工单处理。这些均在小程序完成。关门、返航与自动派车已移至待确认扩展，两端均不生成本期入口。

本平台维护员工准入、基础资料与基础业务规则；“启用账号”不代表受理配送申请。

## 2. 平台结构和权限

### 导航结构

左侧导航依次为：

1. 人员与权限。
2. 基础资料。
3. 营业与业务规则。
4. 既有服务接入。
5. 基础报表。
6. 审计日志。

系统监控、备份和恢复验证通过既有部署工具及运维文档落实，不要求另建可视化运维平台。

顶部栏显示工厂名称、当前账号及账户菜单。不设计多工厂切换，不提供业务角色切换后即可绕过权限的入口。页面内容按实际权限裁剪，导航隐藏与服务端权限校验一致。

### 一人多角色

同一个人可以同时拥有工人、仓库人员、调度人员、管理员等多个角色，关联同一个内部账号。员工角色配置必须使用复选框或多选选择器，不能使用单选下拉框；角色标签全部展示，过多时折叠并可展开。

- 员工归属信息与角色授权范围分别表达。详情按角色列出对应仓库／数据范围，不能只用一个全局仓库字段覆盖所有角色权限。
- 管理平台展示该账号获授权的平台菜单集合，无需退出登录切换账号；没有平台访问权的业务角色不会因为数量多就自动获得后台权限。
- 有效权限必须来自同一授权关系中的操作与数据范围。例如「管理员可查看全厂＋调度仅可操作一仓」不等于可在全厂派车。菜单合并不意味着将所有角色的范围扩给每项操作。
- 新增或移除一个角色不删除账号、不清除历史订单；其他有效角色保留。移除最后一个平台访问授权后退出受限页面，账号被整体停用时所有角色均失效。
- 变更确认逐项列出新增角色、移除角色及各自范围；审计记录真实操作者和授权依据。小程序刷新角色工作区与权限，不要求重复注册。
- 一人多角色不额外引入「申请、审批、派车必须由不同人员完成」的限制；如未来需要岗位互斥或职责分离，再单独明确规则。

### 权限视角

| 权限视角 | 允许查看或管理 | 界面表现 |
|---|---|---|
| 人员和配置管理 | 员工、角色、数据范围、基础资料、规则 | 对有权限项目显示编辑或启停按钮 |
| 报表查看／导出 | 授权仓库或全厂汇总、明细、导出 | 查看与导出权限分开；无导出权限不显示导出操作 |
| 运维与审计 | 系统健康、接入状态、审计、备份与留存 | 只读查询和配置权限分开，不默认授予业务车辆控制权 |
| 无权限或停用 | 不得访问受限页面或业务接口 | 无权限页、账号停用提示或返回登录 |

平台使用原有内部用户和权限体系，具体平台登录方式待确认。原型为统一呈现，可暂采用「管理员手机号＋验证码」演示，这只是登录画板假设，不将其写成必须实现的登录方案；不增加开放注册或强制企业单点登录。

## 4. 页面功能说明

### M01 平台登录与账户

**M01-01 登录**

- 左侧可用系统名称与一句说明「人员、配置、报表与系统管理」，右侧登录卡片。
- 演示方案字段：手机号、验证码；按钮「获取验证码」「登录」。显示准入说明「仅限已开通管理平台权限的内部人员」。
- 覆盖必填缺失、手机号格式错误、验证码错误／过期、限频、请求中、网络失败、账号停用、无管理平台权限和登录过期。
- 登录成功跳转第一个有权访问的页面；不能固定让只有报表权限的账号进入配置首页。
- 验证码有效期、限频和后台认证最终方案待确认，界面不写死未经确认的数值。

**M01-02 账户信息**

- 只读显示姓名、脱敏手机号、全部已授权角色标签，以及各角色对应仓库或全厂数据范围。
- 「退出登录」二次确认；会话失效时阻断保存等动作并提示重新登录。
- 不提供自行升级权限、任意切换仓库归属或把当前账号改为管理员的操作。

### M02 人员与权限

**M02-01 员工列表**

- 筛选：姓名／手机号、仓库、角色、启停状态、绑定状态；「查询」「重置」。
- 表格：姓名、脱敏手机号、所属仓库、多角色标签、账号状态、手机号验证状态、微信绑定状态、更新时间、操作。按某角色筛选时，拥有该角色的多角色员工同样命中，一人只占一行。
- 主操作「新增准入员工」打开 M02-02；行操作「查看」「编辑」「启用／停用」按权限展示。
- 停用确认说明该账号将失去系统访问权限，保留已有订单和历史处理记录；保存后更新状态并留痕。
- 不默认新增批量导入、员工删除或短信邀请能力。

**M02-02 员工详情与编辑**

- 信息区：姓名、手机号、所属仓库、角色多选、按角色配置的授权数据范围、启停状态；内部账号 ID 只读。可同时勾选「工人＋仓库人员＋调度人员」，每个角色展开各自范围设置，不能用新选择覆盖原角色。
- 绑定区：手机号是否已验证、微信是否已绑定；管理员编辑手机号不等于完成验证，不提供「手动标记已验证」。
- 授权多仓库以原权限体系实际支持为准，采用可选列表，不能把选择仓库当成扩展账号权限的旁路。
- 提交前展示变更摘要：归属变更、新增／移除角色、各角色范围变更、启停变化；记录操作者和时间。取消编辑不改变任何现有角色。
- 覆盖手机号已关联其他账号、必填缺失、失去编辑权限、他人已修改和保存失败。遇到身份冲突不能自动合并账号。

**M02-03 权限矩阵**

- 左侧选择已有角色，右侧按「页面／操作／数据范围」展示权限；此处单选仅用于查看单个角色的权限矩阵，不限制员工只能拥有一个角色。员工详情可汇总多个角色权限并标记来源。
- 业务角色如工人、仓库、调度、管理员沿用现有定义；管理平台访问与配置操作单独体现。
- 原型默认展示系统角色权限并分配给人员，任意新增自定义角色或改写固定角色能力待确认，不默认生成角色编辑器。
- 修改已支持的授权项时显示影响对象和前后变化，再确认保存；不可授予自己无权分配的权限。
- 最后一个有效管理员的保护规则需确认，先在设计备注说明，不编造自动转移管理员机制。

### M03 基础资料

共同原则：维护基础实体及映射，不处理本次订单安排。列表支持查询、分页，编辑抽屉显示数据来源、更新时间与可修改字段。

**M03-01 仓库资料**

- 表格：仓库名称、内部标识、状态、关联人员数／车辆数／点位数、更新时间。
- 维护仓库名称、说明及启停状态；标识唯一且不作为可随意改写的展示文字。
- 停用前展示关联影响和正在使用情况，发生业务冲突时阻止并提示由小程序处理相关业务后再操作。停用不取消订单、不删除历史记录。
- 仓库负责人等字段仅在实际基础资料已提供时展示，不新增未经确认的组织层级。

**M03-02 停靠点管理**

- 筛选仓库、可用状态、绑定状态。
- 表格：点位名称、所属仓库、外部点位标识、位置说明、绑定情况、可用状态、同步时间。
- 从实际可达的外部点位中绑定内部停靠点；不能自由输入地址就建立车辆任务目的地。
- 无外部点位、同步失败、绑定冲突和已被停用分别呈现；不默认提供地图画路线或新建车辆道路网络能力。
- 停用不修改历史订单地址，新的申请不得选择已停用点位。

**M03-03 车辆档案**

- 表格：车辆展示名称、外部车辆标识、所属仓库、格口数量、接入／同步状态、更新时间。
- 可维护已有车辆的本地显示名及授权归属；厂商车辆标识和硬件能力只读或通过既定同步更新。
- 详情提供基础属性、来源、绑定关系、最后同步结果；不提供派车、取消、开关门或返航按钮。
- 归属变更前展示关联影响；当前任务冲突时阻止直接变更，不把车辆移仓操作当成终止任务。

**M03-04 格口定义与同步**

- 选定车辆后展示真实格口编号、有效性、来源、同步时间及差异说明。
- 「同步资料」仅刷新基础定义，不下发车辆控制命令。同步新增／缺失／变化用对比表呈现。
- 不允许凭空添加设备不存在的格口；具体哪些映射字段可人工维护按接口资料确认。
- 本页面不出现订单选择器；本批订单分配到哪个格口在小程序完成。

### M04 规则配置

共同结构：适用范围、当前生效值、编辑值、单位、说明、修改人／时间。保存前校验，成功后显示生效结果；未保存离开需确认。并发版本冲突提示刷新后重新编辑，不能静默覆盖。

**M04-01 营业与预约配置**

- 按仓库配置开放营业时段，以及半小时一档的预约容量；预约粒度保持原需求的 30 分钟。
- 使用日期／星期安排与时段表呈现，具体开放日期范围取业务确认值，未设置时显示「未配置」。
- 校验结束晚于开始、时间段不重叠、容量格式和范围合法。
- 变更预览显示对可预约时段的影响；已有订单不被自动取消或改期。涉及容量减少等已预约冲突时提示并要求按确认规则处理，不能静默挤掉订单。

**M04-02 业务参数**

- 分组：货物描述／大小／备注文字上限、未取货超时、车辆状态新鲜度、门状态新鲜度及已支持的其他校验参数。
- 每项显示名称、当前值、单位、适用范围、说明。秒、分钟、字符数不可混淆；不在原型固化未经确认的阈值。
- 未配置的关键参数提示先完成配置；保存失败保留输入，不显示已生效。
- 数据超时阈值的修改不能让未知状态变成已知，更不能绕过车辆控制的必要校验。

### M06 既有服务接入

**M06-01 服务接入**

- 仅维护九识车辆 API、状态推送、普通小程序首页入口和登录验证码所需配置。
- 展示接入状态、最近检查时间和配置完整性；未知、鉴权失败、超时、参数缺失分别呈现。
- 凭证由安全渠道维护，界面不返回明文密钥；只读连通性验证不得通过派车、开门或发送业务短信执行。
- 本期不提供地图、轨迹、预测、业务短信、微信订阅、免登录、车辆直达或自动派车的服务卡片与能力开关。

### M07 基础报表与导出

**M07-01 汇总报表**

- 按日期、车辆和授权仓库查询基础订单统计，区分完成、取消、异常的实际口径。
- 展示对应业务列表和汇总，订单数量与合单后的车辆任务数量不可混淆；不增加定制大屏、配送效率分析、准时率或车辆利用率。
- 可从指标查看只读明细；导出 Excel 前确认筛选条件和数据范围，成功下载，失败提示重试。
- 保留操作者、时间、条件与结果审计；不要求独立异步任务中心、文件到期管理或重新生成历史任务流程。

**M07-02 只读明细**

- 展示订单、任务、工单关系及处理履历，标明只读；保留数据权限及敏感信息脱敏。
- 不在报表中受理订单、派车、关闭工单或修改业务完成状态。

### M08 审计与运行维护

**M08-02 审计日志**

- 按时间、操作者、模块、动作、结果和关联对象查询操作及配置记录。
- 详情保留变更前后值、原因、操作者、时间与实际结果；禁止无痕修改。
- 凭证、验证码、令牌不进入普通日志，个人信息按权限脱敏。

**基础运维交付（不要求独立自建画板）**

- 按标准版交付 API/MQTT 连接与错误监控、服务日志、数据库备份和配置管理。
- 备份频率、保留周期与恢复目标在部署方案中确定，并进行恢复验证。
- 业务记录至少在线保留 31 天，未完成记录继续保留；起算口径按业务确认值，不据此承诺连续历史轨迹存储。
- 通过既有部署工具、日志及运维文档证明结果。不新增自建系统健康首页、告警处理工作台、可视化备份管理或生产控制按钮。

## 5. 全局组件和状态

| 组件或状态 | 设计要求 |
|---|---|
| 列表 | 顶部筛选、查询／重置、结果数、分页、固定操作列；宽表允许横向滚动 |
| 编辑 | 短表单用抽屉，复杂规则用独立页；必填明确，错误贴近字段 |
| 变更确认 | 展示对象、前后差异、影响范围和说明，再确认保存 |
| 未保存离开 | 提供继续编辑／放弃更改，不静默丢失输入 |
| 保存中 | 禁止重复提交，成功后展示实际生效状态 |
| 并发冲突 | 提示内容已更新，查看最新版本后重新编辑，不静默覆盖 |
| 请求结果未知 | 提示待核对，先刷新确认实际配置，不直接显示保存失败并鼓励反复提交 |
| 权限失效 | 阻断操作，说明无权限并返回可访问页面 |
| 未配置／不支持 | 分别说明原因，能力开关不能绕过依赖 |
| 数据未知／过期 | 显示未知或上次检查时间，不用 0 或绿色正常替代 |
| 空数据 | 无员工／报表无结果／无日志等使用场景化文案 |
| 只读业务记录 | 统一只读标记，没有执行日常业务的按钮 |
| 错误反馈 | 使用可理解的说明；技术详情仅运维权限可见且脱敏 |

账号启停、基础资料停用和业务状态是不同对象；保存配置不自动完成订单或触发车辆动作。

## 6. 本期原型流程

1. 人员授权：员工查询 → 准入／角色与范围编辑 → 确认保存 → 审计；覆盖冲突、无权限和停用。
2. 基础资料：查询／同步 → 核对实际字段和绑定 → 确认业务配置 → 查看结果；不增加九识点位创建或地图作业。
3. 预约与参数：编辑营业时段、容量或阈值 → 校验 → 确认 → 保存；不自动取消已有订单。
4. 既有接入：查看配置与接入状态 → 核对缺项 → 安全维护配置 → 只读验证／查看错误记录。
5. 基础报表：筛选 → 汇总 → 只读明细 → 确认导出 → 下载／失败提示；保留导出审计。
6. 审计查询：筛选 → 详情 → 关联业务只读追溯。
