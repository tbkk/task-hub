# 标准版完整开发执行范围

## 授权与需求基线

2026-09-20 用户要求继续当前分支完成全部开发计划，明确九识接口和测试车辆暂未具备，先完成模拟闭环。继续使用 `feature/base`，本次不按模块新建分支。管理平台采用内部账号＋密码，微信 AppID 和短信服务尚未准备好，当前不使用 Docker。

需求基线沿用 `docs/design/中集系统功能端划分建议.md` V2.2、小程序界面说明 V3.2、管理平台界面说明 V1.2，整体路线图为 `docs/superpowers/plans/2026-09-20-development-roadmap.md`。这些已授权的范围不重新要求确认。

## 交付结构

- 后端：数据库持久化身份、权限、基础资料和业务记录；接口级和逐角色数据级授权；有序迁移、幂等和并发保护。
- 小程序：完成工人、仓库、调度、概览四工作区与消息、个人中心，沿用 Figma 和已有通用组件。
- 管理平台：人员权限、基础资料、配置、只读报表及导出、审计；不增加日常业务操作入口。
- 第三方提供者：微信、短信、车辆使用可替换适配器。模拟状态、超时和失败明确标识，请求受理与实际状态独立保存，生产禁止启用开发模拟路径。
- 本地验证：三端测试与构建、MySQL 迁移、浏览器主流程、模拟闭环、权限和失败路径、备份恢复演练。

## 实施策略

采用模块化单体和现有 Vue/uni-app 工程，按后端、小程序、管理端分别编写详细计划；先统一接口契约，再实现可以独立验证的业务切片。业务数据落 MySQL，模拟仅用于外部提供者；保留现有前端基础演示模式，但不得把纯客户端数据作为后端持久化验收。

不引入微服务、Redis、Docker 或新的 UI 框架。各端集中服务适配，页面不自行拼装权限。状态机分别表达订单、取消申请、批次、派发请求、任务、控制请求和工单。状态变化和审计同事务保存。

## 交付边界

没有真实凭证或设备时，完成适配接口、模拟器、部署说明和验收步骤；真实微信、短信、车辆 API/MQTT、真机实车验收保持“外部依赖阻塞”。不伪造接入成功，不把路线图阶段 8 整体标记为已完成。

业务未冻结参数采用可配置的演示值并标注来源，发布前需要业务确认。在线业务记录至少保留 31 天；本阶段不启用自动删除，避免未确认起算口径导致历史数据丢失。共享格口按独立格口演示，保留后续确认点。

## 验收目标

1. 同一账号多角色不串仓，停用和撤权及时生效；管理权限不授予日常车辆控制权。
2. 申请 → 受理 → 成批 → 格口分配 → 装货 → 人工派发 → 模拟到站 → 授权取货形成可查询闭环。
3. 取消申请保留原主状态直到仓库处理；反馈工单不自动完成、取消或重派订单。
4. 开门、继续出发和任务取消验证当前身份、任务、位置、状态时效与阻断条件，超时保持待核对。
5. 主流程之外覆盖失败重试、幂等、并发冲突、跨仓越权、旧状态推送、权限失效、空状态和窄屏。
6. 配置变更、业务履历、消息、统计和导出有真实数据依据，管理员编辑手机号不直接赋予验证状态。
