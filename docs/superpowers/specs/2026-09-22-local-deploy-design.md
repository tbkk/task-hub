## 命令与发布流程

- `deploy`：校验配置、依赖和端口；构建并验证管理端/H5/Java 产物；暂存完整发布；检查 Nginx 配置；停止本脚本托管服务，启动新后端并检查 ready，再发布静态资源、启动 Nginx，检查两个页面和 API。默认命令为 deploy。
- `restart`：复用已有发布产物，重新读取配置并重启，不重新构建。
- `stop`：只停止核实归属的本项目 Java 与 Nginx，不停止 MySQL或其他项目进程。
- `status`：报告托管进程与两个站点、后端就绪情况，异常返回非零。
- `logs`：提供运行日志位置和有限最近输出，不输出配置文件或进程环境。

依赖检查提示缺失组件；不擅自安装系统软件。依赖缺失时明确提示前端执行 npm ci。构建失败保留已运行版本；启动失败返回非零并保留诊断日志，不宣称成功。保留上一份发布产物用于人工恢复，不承诺数据库自动回滚。

## 配置、数据与进程边界

本地配置采用受限 KEY=VALUE 解析，不执行 shell 插值或任意命令；配置项只支持部署需要的白名单。端口、路径、数据库及模拟配置启动前验证。运行目录不得指向仓库根、用户主目录或系统宽目录；运行文件使用受限权限。

沿用 Flyway 增量迁移，启动日志记录执行结果；不删库、不重建库、不运行初始化数据脚本，不把测试套件连接到实验数据库。管理员已存在时复用，不自动重设密码。缺少管理员时提示已有受控初始化入口。

默认停止进程前同时检查 PID 与命令归属；端口被非托管进程占用时报告冲突。2026-09-22 用户追加要求参考 Puck 增加 `--force`：仅允许 `--force deploy`（省略 deploy 同义），构建及 Nginx 预检成功后，允许终止后端 PID 文件记录的存活进程（即使归属不符）和配置后端端口的监听者；先 TERM，15 秒后仍存活则 KILL。前端端口、Nginx 归属和部署锁仍维持检查，其他命令拒绝 --force。此为用户明确授权的可选行为，不在普通 deploy 自动启用。部署互斥，不修改 Homebrew 的全局 Nginx 配置。
