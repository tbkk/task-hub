# 账号密码登录与管理员重置密码设计

## 目标

取消小程序正常登录对短信服务的依赖。员工使用管理员开通的内部账号和密码登录；管理员重置密码后立即使该员工全部旧会话失效，并要求员工使用临时密码重新登录后修改密码。

## 范围

- 小程序登录页增加账号、密码登录，登录成功后沿用现有会话和工作区恢复逻辑。
- 小程序增加首次改密页；`mustChangePassword=true` 时只允许访问身份查询、改密和退出。
- 管理员重置员工凭据时撤销该员工全部会话，包含小程序和管理端会话。
- 管理端现有内部账号登录、人员凭据重置和首次改密流程继续复用。
- 微信登录保留为可选绑定入口；短信登录保留兼容接口，但不再作为默认登录入口。

## 不包含

- 不新增公开注册、默认账号、固定生产密码或客户端 token。
- 不在生产环境启用模拟验证码或快捷登录。
- 不改变员工角色、仓库范围和业务权限模型。

## 接口与状态

- `POST /api/admin/auth/login` 接收 `{username,password}`，返回现有 `Session`。
- `POST /api/identity/password` 接收 `{currentPassword,newPassword}`；成功后撤销当前员工所有会话，客户端回登录页。
- `POST /api/admin/employees/{id}/credentials` 接收 `{username,temporaryPassword}`；仅平台 `EMPLOYEE_MANAGE` 可用，设置 `mustChangePassword=true` 并撤销该员工所有 `auth_session`。
- 临时密码会话由服务端 Bearer 过滤器限制，仅允许 `/identity/me`、`/identity/password` 和退出接口。

## 前端交互

- 登录页默认显示账号密码表单；失败保留账号，清空密码并展示结构化错误。
- 员工首次登录后进入改密页，当前密码使用临时密码；新密码至少 12 个字符且不能与当前密码相同。
- 改密成功清空本地会话并回到登录页，员工用新密码重新登录。
- 管理员重置密码后，原设备下一次请求收到会话失效并回到登录页；不会继续使用旧会话。

## 验证

- 后端测试覆盖正确/错误密码、管理员重置撤销全部会话、临时密码限制、改密后新密码登录。
- 小程序测试覆盖登录表单、首次改密跳转、失败保留账号、改密后清理会话。
- 三端类型检查、构建和既有交付验证继续执行。
