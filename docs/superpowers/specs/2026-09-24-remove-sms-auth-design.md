# 完全移除短信认证设计

## 背景与目标

当前小程序仍有手机号验证码登录，以及未绑定微信时通过手机号验证码绑定微信两条短信链路。账号密码登录已经成为默认入口，但短信接口、配置、数据库表和前端页面仍可被调用。本次移除全部短信认证能力，保证运行时、前端入口、配置文档和测试中不再依赖短信。

## 方案

微信登录接口继续先交换微信凭证。已绑定微信时直接签发小程序会话；未绑定微信时继续返回一次性、短期绑定令牌，但状态改为 `CREDENTIALS_REQUIRED`。小程序跳转到绑定页，用户输入已由管理员开通的内部账号和密码，客户端提交令牌、账号和密码到 `POST /api/mini/auth/bind`。服务端在事务内校验令牌、账号密码、员工启用状态及微信绑定冲突，成功后写入 `employee_wechat` 关系、消费令牌并签发 `MINI` 会话。

账号密码绑定复用现有 BCrypt 凭证校验和员工准入规则。临时密码账号不能绕过首次改密约束：绑定接口只允许已完成首次改密的账号；若账号仍标记为临时密码，返回明确错误并要求先用账号密码登录修改密码。绑定成功不修改手机号，也不创建短信挑战。

## 移除范围

- 删除小程序手机号登录页及路由。
- 删除前端短信 API、短信状态、mock 验证码逻辑和相关类型。
- 删除后端 `/api/mini/auth/sms`、`/api/mini/auth/verify` 及对应服务方法、provider 注入、限频和短信配置。
- 删除短信 provider 配置、环境示例、短信挑战 mapper/模型和数据库表；新增 Flyway migration 删除既有 `sms_challenge` 表，兼容已升级环境。
- 更新 API 契约、README、集成就绪文档、验收矩阵和相关设计文档，明确认证仅使用账号密码和微信绑定。
- 删除短信集成测试，补充账号密码绑定成功、错误密码、临时密码、令牌过期、重复绑定和冲突场景测试。

## 错误处理与安全

- 绑定令牌随机生成、哈希存储、十分钟过期、单次消费，沿用现有绑定表机制。
- 账号不存在、密码错误、账号停用、临时密码和绑定冲突分别返回现有身份错误语义，不泄露手机号或凭证细节。
- 接口不返回密码、密码哈希、微信 openid 或绑定令牌明文以外的敏感信息；成功响应只返回会话。
- 删除安全白名单中的短信路径，绑定接口作为公开认证入口加入白名单；请求频率沿用账号密码登录的 IP/账号限频。

## 验证策略

- 后端 IdentityIT/MiniAuthIT 覆盖绑定成功和全部失败分支，MigrationIT 验证升级后短信表被删除。
- 小程序单元测试验证微信未绑定跳转账号密码绑定页、绑定成功进入首页、失败提示和无短信 API 调用；执行类型检查、H5 构建和微信构建。
- 全仓 `rg` 检查运行代码、配置和文档不再出现短信认证入口或配置名；仅历史需求文档中的非认证通知说明可保留并标注为非本期能力。
