# 小程序完整业务交付设计

日期：2026-09-20。状态：实施设计，尚未编码。适用分支：`feature/base`。

## 1. 目标与范围

在阶段 1 登录、工作区和公共组件基础上，交付小程序 P03–P17、P19、P20、P22–P29、P33、P34、P40，打通申请、仓库处理、装货派发、扫码取货、车辆控制、工单、消息、概览和履历查询。业务事实全部来自服务端 MySQL；客户端现有演示数据只保留为基础交互演示，不作为订单、批次、任务或工单持久化。

本期不新增地图、轨迹、ETA/到达倒计时、远程关门、返航、微信订阅、业务短信、任意地址、代取授权、自动派车或九识指定车辆直达。九识入口只打开普通首页。真实微信、短信、车辆资源缺失时使用服务端开发模拟器完成闭环，并把真机/实车验收记为外部依赖阻塞。

## 3. 架构

沿用 uni-app、Vue 3 和 TypeScript，不引入状态库或 UI 框架。页面只负责展示、输入和导航；接口调用集中在 `src/services/`，跨页业务状态和格式化逻辑集中在 `src/features/`。每个业务域由纯 TypeScript 模型/映射、API 适配器和 Vue 页面组成，纯逻辑通过 Node test 验证。

```text
页面 / 组件
    ↓ 调用、展示
features/{order,batch,dispatch,ticket,...}
    ↓ 业务类型、动作判断、展示映射
services/{session,order,batch,...}.ts
    ↓ 自动附加 Bearer、X-Workspace、幂等键
services/request.ts
    ↓
/api（服务端鉴权、范围、状态与并发为最终边界）
```

客户端不会根据本地角色扩大权限。服务端 `allowedActions` 决定动作入口，页面仍显示不可操作原因；写请求提交时服务端再次鉴权和校验版本。

## 4. 目录与职责

### 4.1 共享层

- `src/services/request.ts`：统一解包 `{code,message,data}`，注入内存 token 和 `X-Workspace`，处理 `40101/40301/40302` 失权退出；写请求接收 `idempotencyKey`。
- `src/services/session.ts`：仅内存保存 opaque token；偏好的工作区仍可本地保存，token、订单和车辆数据不落本地存储。
- `src/services/types.ts`：`Page<T>`、`EntityId`、`Versioned`、错误数据等公共协议。
- `src/features/common/idempotency.ts`：一次用户确认生成 UUID，同一次失败重试沿用，获得确定结果后清除。
- `src/features/common/paged-query.ts`：替换式刷新、追加分页、空/失败/末页状态；工作区变化时丢弃旧结果。
- `src/features/common/presentation.ts`：时间、未知值、手机号遮罩和服务端枚举中文映射。未知数值不得显示为 0，未知门状态不得显示为关闭。
- `src/components/`：补充业务页面壳、筛选栏、列表状态、时间线、固定操作栏、条件检查行、车辆/格口卡；复用现有按钮、表单、确认框、状态标签和状态面板。

### 4.2 业务域

- `features/catalog`：仓库、点位、时段、规则、收藏。
- `features/order`：申请草稿、订单、取消申请、取货及订单展示状态。
- `features/batch`：受理、批次成员、装货与格口分配。
- `features/dispatch`：派发请求、任务、车辆快照、控制请求和继续出发条件。
- `features/ticket`：工人工单和仓库处理。
- `features/notification`：消息、未读数和授权跳转。
- `features/report`：概览和业务履历。
- `features/integration`：九识普通首页跳转和返回刷新。

每个域的 `api.ts` 只导出契约对应函数；`model.ts` 定义 DTO 与纯映射；页面不得直接调用 `uni.request`。

## 5. 路由与页面归属

主包保留消息和个人中心，并增加消息详情。工人分包包含申请、选择点位/时段、结果、订单、扫码、取货、继续出发、反馈、工单和收藏；仓库分包含工作台、审批、批次、装货和工单处理；调度分包含选车派发、任务、车辆与控制；概览分包含概览、筛选明细和履历。

同一个视觉状态不机械拆成路由：确认、失败和结果未知优先使用组件或当前页状态；需要返回、刷新或分享上下文的实体详情使用独立路由。所有实体 ID 作为字符串传参，进入详情后重新请求，禁止把完整实体序列化到 URL。

## 6. 网络、会话和错误处理

请求统一发送 `Authorization: Bearer <opaqueToken>` 和当前 `X-Workspace: worker|warehouse|dispatch|overview`。token 只保存在内存，应用重启重新登录；本地存储只保存仍需服务端核验的工作区偏好。页面加载前调用现有访问守卫，接口仍以服务端授权为准。

创建、派发、取货确认和所有车辆控制使用 UUID `Idempotency-Key`。编辑/动作正文携带详情最新 `expectedVersion`。规则如下：

- `40101/40301/40302`：清会话及工作区业务缓存，提示登录失效或权限变化，重启到登录/工作区选择。
- `40901`：提示请求内容与重试不一致，不换 key 绕过。
- `40902/40903`：保留输入，刷新当前对象并要求用户重新确认。
- `42201`：保留申请其余字段，仅清除失效时段并返回选择。
- `42202/42203/42204`：显示服务端 `blockers`，禁用控制，允许刷新状态。
- `42901`：显示服务端限频说明，不自动密集重试。
- 网络失败：查询可重试；写操作若无法确定服务端是否收到，先按对象重新查询。车辆类请求使用服务端返回的 `UNKNOWN` 展示“待核对”，只调用 reconcile，不重新发送控制。

## 7. 业务状态与页面语义

### 7.1 订单和取消

订单状态 `PENDING/ACCEPTED/READY/IN_TRANSIT/AWAITING_PICKUP/COMPLETED/REJECTED/CANCELLED` 映射为待受理、已受理、待发车、配送中、待取货、已完成、已驳回、已取消。取消申请 `PENDING/APPROVED/REJECTED` 是附加状态；提交取消后继续展示原订单主状态，只有批准后订单才显示已取消。

申请失败保留全部草稿；时段失效只要求重选时段。接收人未绑定仍允许创建订单，但明确显示暂不能扫码取货。订单列表按“我申请/我接收”关系呈现，服务端只返回本人有权读取的数据。

### 7.2 批次、装货和派发

批次状态和装货状态分别展示。编辑批次只允许同仓、同点、同时段订单；任务请求已下发或结果未知时锁定成员。选车和格口分配保存为完整覆盖，换车后清除旧格口选择并重新确认装货。

装货开门请求、派发请求和车辆真实状态相互独立。`RequestStatus` 的 `ACCEPTED` 仅表示请求被受理；门是否打开读取 `Vehicle.doors`，车辆是否运行读取 `VehicleTask.state` 和车辆新鲜状态。`UNKNOWN` 进入待核对状态。

### 7.3 扫码、取货和继续出发

二维码格式由后端验证，扫码只识别车辆。`POST /pickup/scan` 返回当前账号本人可操作订单及阻断原因。开门由订单推导格口，不允许工人自由选格口；取货确认逐单完成。

继续出发按钮只有在服务端返回无 blockers 且页面拥有允许动作时启用。必须同时满足本人/调度权限、AT_STOP 与任务/点位匹配、本站所有订单已取、相关门关闭且新鲜、无活动工单、下一点明确、无未决 GO 请求。本人已取但他人未取时保留本人完成状态并显示阻断。

### 7.4 车辆控制

调度开门、继续出发和取消任务都经过详情刷新、条件展示、二次确认和独立控制请求。取消任务要求速度明确为 0 且车辆在线/新鲜；取消成功不自动取消订单。远程关门与返航无入口。

### 7.5 工单、消息、概览和履历

反馈工单不修改订单或车辆。重复提交同订单活动工单时打开已有工单。关闭必须填写结果，服务端版本冲突后刷新，不覆盖他人处理。

消息按账号聚合；进入详情调用已读接口。目标失权时仍可读消息正文，但不跳转实体。跨工作区目标先提示切换并复用现有未保存内容确认逻辑。

概览分别显示订单、批次、任务和活动工单统计，指标点击带固定筛选进入列表，不把任务数写成订单数。履历读取服务端裁剪后的记录；更正记录只展示原值、新值、原因和操作者，小程序不提供更正写入口。

## 8. 页面状态和交互约束

所有列表和详情覆盖 loading、empty、error、content 四态；分页追加失败保留已有内容。所有写操作使用局部 busy，禁止重复点击，失败保留输入。控制类操作还需覆盖 accepted、failed、unknown 和实际状态确认。

页面从后台返回、九识小程序返回或扫码返回时重新读取相关实体。请求响应到达时校验当前工作区与实体 ID；切换角色后的旧响应不得写回。窄屏用固定操作栏和可换行标签，320px 不产生横向滚动。

视觉以 Figma 各节点为准：实现某任务前按索引读取该任务节点；复用统一 token 和组件，不从截图猜测未核实尺寸。图标使用项目已选择的图标方案，不能用占位字符作为最终业务图标。

## 9. 对端接口依赖和契约缺口

直接依赖 `docs/api/delivery-contract.md` 全部小程序接口。后端必须在对应小程序切片联调前可用，并准备当前账号/角色/仓范围、点位时段、车辆格口和模拟事件数据。

当前契约需要在实现前补充以下读取字段或聚合 DTO；客户端不能通过额外越权请求拼装：

1. `Order` 页面需点位名、仓库名、申请人/接收关系、车辆显示名、订单事件时间线、活动工单摘要及距离/参考耗时展示字段；手机号需由服务端按角色脱敏。
2. `Batch` 详情需订单摘要、点位/时段显示值、车辆/格口可选项与各订单取货状态；只返回当前仓授权数据。
3. `VehicleTask` 详情需目标点序列、关联订单安全摘要、控制请求和实际反馈时间线。
4. `Ticket` 详情需处理人、受理/说明/关闭时间线。现有 `POST /tickets/{id}/notes` 返回的说明也应能在详情读回。
5. `Message.target.workspace` 已可驱动跳转，但需明确目标实体失权时 `target=null` 的稳定行为。
6. `POST /pickup/scan` 的 `canContinue/blockers` 可作为扫码页条件；车辆详情控制页也需要同口径的 `allowedActions/blockers`，避免客户端复制规则。
7. `GET /integration/mini-entry` 只给 appId/mode；开发模拟跳转结果需要确定由客户端场景开关模拟，且生产构建不可出现可操作模拟入口。

这些是契约细化，不改变已确定的 URL、身份头、ID 字符串、分页、版本和幂等规则。

## 10. 测试策略

- 纯逻辑测试：请求头、失权清理、错误映射、分页去重、状态中文映射、申请校验、批次同组约束、格口完整分配、控制请求语义、消息跳转和概览筛选。
- 页面交互：表单保留、busy、防重复、冲突刷新、空状态、分页、跨工作区、扫码取消/无权限、控制 unknown/reconcile。
- 构建：每个切片执行 `npm test`、`npm run typecheck`；阶段门执行 H5 和微信生产构建。
- 浏览器：390px 和 320px 检查流程 A–H、J，确认无横向溢出、固定操作栏不遮挡内容。
- 联调：使用真实后端和 MySQL 验证数据持久化、跨仓拒绝、停用/撤权、幂等和并发冲突；服务端模拟器验证超时、失败、重复和乱序事件。
- 外部验收：微信开发者工具/真机、九识真实跳转和实车控制在资源到位后执行；模拟通过不标记真实验收通过。

## 11. 完成定义

所有范围页面和状态可从四工作区进入；流程 A–H、J 使用服务端 MySQL 数据跑通；订单、取消、批次、派发、任务、控制、工单状态没有被压成单一状态；取货仅本人；继续出发和取消任务由服务端条件约束；失权立即退出；查询具备空状态/分页，写操作具备 busy/失败保留输入/幂等；测试、类型检查、H5/微信构建和浏览器窄屏检查通过。真实外部资源缺失项明确列为阻塞。
