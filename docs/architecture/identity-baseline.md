# 身份与权限实施基线

2026-09-20，阶段 2 前置设计。管理端和小程序登录均采用“内部账号＋密码，由管理员开通”；微信仅作为绑定后的快捷入口。

## 已确定的契约原则

- 一名员工一个内部身份，微信、手机号和管理端账号关联到同一身份，不创建各端互不关联的业务账号。
- 小程序微信认证提供者尚未就绪，开发可替换为 mock；生产配置禁止固定模拟微信身份。
- 管理账号存密码哈希，不存明文；采用 Spring Security 密码编码器。首次管理员通过受控初始化命令创建，初始凭证由环境传入，不提交默认账号密码。
- 会话由后端发放并验证，客户端工作区角色不是授权凭证。停用、退出和失效必须在后端生效。
- 授权记录按员工、角色、数据范围关联。操作能力与范围来自同一条角色授权，禁止角色 A 的操作能力与角色 B 的全厂范围合并。
- 工人数据范围受本人申请/指定接收关系约束；仓库和调度分别使用所分配的仓库；概览只读授权范围内的业务。
- 管理平台访问和人员配置等能力独立于日常业务角色。管理员不能绕过取货关系或车辆控制前置条件。
- 权限撤销后的查询/操作立刻拒绝；客户端刷新授权并清空原工作区缓存。恢复上次工作区只恢复仍有效的角色。

## 第一批服务接口（拟定）

统一响应 `{ code, message, data }`；业务 ID 为字符串，失败同时返回相符 HTTP 状态。

| 方法与路径 | 用途 | 约束 |
| --- | --- | --- |
| POST /api/admin/auth/login | 内部账号与密码登录 | 统一认证失败提示、失败限频，不泄露账号存在性 |
| GET /api/identity/me | 查询当前身份与逐角色授权 | 验证有效会话与员工启停状态 |
| POST /api/identity/logout | 撤销当前会话 | 重复退出保持安全，不撤销其他人的会话 |
| POST /api/mini/auth/wechat | 交换微信临时码 | 凭证仅服务端使用，未绑定返回短期绑定流程凭据 |
| POST /api/mini/auth/bind | 账号密码绑定微信并登录 | 校验一次性绑定凭据、账号密码、员工准入与绑定冲突 |

具体请求/响应模型和认证凭据载体在阶段 2 的详细实施计划中冻结；本文件不声称上述接口已实现。

## 数据与验证

拟按依赖顺序迁移员工、管理登录凭据、外部身份绑定、会话、角色授权及仓库范围关系表；其他业务表按模块新增。管理员更改手机号不能自动标记已验证，已有绑定发生冲突时不得自动合并身份。

本机检测到 MySQL 9.6.0，监听本地 3306；工程目标仍是 MySQL 8.4。不得修改已有其他数据库。本地验证如使用 9.6，应记录实际版本，并在发布前对目标 8.4 验证迁移和查询兼容性。当前阶段不依赖 Docker。

测试必须覆盖账号密码正确/错误、停用、会话撤销、跨仓越权、多角色范围隔离、授权变更、绑定令牌重放/过期和绑定冲突。
