# 中集内部调度系统用户操作手册

适用版本：2026 年 9 月 22 日，本地演示环境。

适用人员：管理平台管理员、工人、仓库人员。

本手册按照当前已开放的页面编写。现在可以进行资料配置、配送申请、仓库审批、取消处理和配送组批。装货、派车、扫码取货等后续页面尚未开放，组批完成后请停止本轮页面演练。

## 一、从哪里进入

| 使用人员 | 入口 | 登录方式 |
| --- | --- | --- |
| 管理员 | [管理平台](http://127.0.0.1:18090/) | 内部账号和密码 |
| 工人、仓库人员 | [小程序 H5](http://127.0.0.1:18091/) | 手机号验证码登录 |

以上链接仅适用于部署系统的这台电脑。其他电脑或手机请使用环境管理员提供的访问地址。

账号、准入手机号和本地模拟验证码由环境管理员提供。演示环境不发送真实短信，请使用「手机号验证码登录」；当前不使用「微信登录」验证真实微信身份。操作产生的订单会保存，演练时请在货物描述中注明“演示”，便于识别。

### 不同入口分别做什么

- 管理平台用于人员、权限、仓库、点位、车辆和规则配置。
- 小程序工人工作区用于申请、查单和申请取消。
- 小程序仓库人员工作区用于受理、驳回、取消审核和组批。

管理平台登录成功，不代表账号同时具有工人或仓库人员角色。各角色需要单独授权；菜单是否显示取决于当前账号权限。

## 二、第一次使用前的准备

管理员先完成下表检查。已有资料时核对即可，不必重复新增。

| 准备事项 | 管理平台菜单 | 完成后应满足 |
| --- | --- | --- |
| 建立供货仓库 | 仓库资料 | 仓库存在且启用 |
| 配置配送目的地 | 停靠点资料 | 停靠点启用并关联供货仓库 |
| 配置可配送车辆 | 车辆资料 | 车辆启用、归属该仓库，且可达停靠点包含申请目的地 |
| 设置预约规则 | 营业与业务规则 | 已保存营业时段、预约天数和每半小时申请容量 |
| 开通工人 | 人员与权限 | 员工启用、准入手机号正确、有工人角色且已选所属仓库 |
| 开通仓库人员 | 人员与权限 | 员工启用、有仓库人员角色，操作范围包含该仓库 |

硬件格口与装货点可提前维护，但当前手册的页面演练只进行到组批，不要求实际开门、装货或发车。

## 三、管理员操作

### 3.1 登录管理平台

1. 打开管理平台，输入内部账号和密码。
2. 点击「登录管理平台」。
3. 如果系统要求修改临时密码，先按页面提示完成修改，再重新登录。
4. 登录后，从左侧菜单进入已授权的模块。

账号密码错误时，先核对输入；多次失败后可能需要等待限频解除。忘记密码时联系有人员管理权限的管理员处理。

### 3.2 维护仓库

1. 进入「仓库资料」。
2. 点击新增入口，或在已有仓库行点击「编辑」。
3. 填写名称、仓库编码，确认「可用状态」。
4. 保存后点击「刷新列表」，核对名称和状态。

供工人申请使用的仓库应保持启用。遇到占用或关联业务提示时，按提示核对相关业务，不要通过重复保存强行覆盖。

### 3.3 维护停靠点与车辆

**停靠点：**

1. 进入「停靠点资料」，新增或编辑点位。
2. 填写名称，选择已有的外部点位。
3. 设置「关联仓库」及「可用状态」，保存。

**车辆：**

1. 进入「车辆资料」，新增或编辑车辆。
2. 填写名称，选择已有的外部车辆。
3. 设置「关联仓库」，勾选该车辆的「可达停靠点」。
4. 确认启用并保存。

工人能选择的目的地必须同时满足：点位启用、点位关联员工所属仓库、该仓库存在启用车辆且车辆可达该点位。只建立停靠点、没有配置车辆可达关系，目的地仍可能不显示。

当前外部车辆和点位来自本地模拟目录。目录中没有需要的项目时联系环境管理员，业务人员不能在申请页自由填写地址来替代点位。

### 3.4 配置营业与业务规则

1. 进入「营业与业务规则」，选择仓库。
2. 核对营业时段，按页面填写星期、开始时间和结束时间。
3. 设置每半小时申请容量、可预约天数及货物描述等文字长度限制。
4. 保存后重新读取，核对已生效的内容。

页面提示“尚未配置规则”时，下方建议值尚未生效，必须补充营业时段并保存。预约只选择未来可用时段；当天已过时段、非营业时段或已满时段不能使用。

页面中的车辆状态有效期、门状态有效期等参数应由负责业务规则的人员确认后调整，不需要普通申请人修改。

### 3.5 开通员工并配置所属仓库

1. 进入「人员与权限」。
2. 点击「新增准入员工」，或搜索姓名/手机号后点击已有员工的「编辑」。
3. 填写姓名、准入手机号，确认账号启用。
4. 在「所属仓库」中选择员工申请配送所用的仓库。
5. 在「业务角色 · 可多选」中勾选所需角色。
6. 给仓库人员等角色设置实际负责的仓库范围。
7. 点击「保存变更」，核对确认信息并完成保存。

保存后通知员工回到小程序重试，必要时退出重新登录。

| 配置 | 含义 | 举例 |
| --- | --- | --- |
| 所属仓库 | 工人申请时自动使用的供货仓库 | 员工向 A 仓申请配送 |
| 仓库人员的指定仓库范围 | 允许该员工审批和组批的仓库 | 仓库人员可以处理 A 仓订单 |
| 管理平台能力 | 允许进入管理平台维护哪些资料 | 允许维护人员，或维护仓库资料 |

三项配置分别生效。勾选仓库人员角色不能代替工人的所属仓库配置；只选择所属仓库也不会自动获得审批权限。当前一个工人只使用一个所属仓库，申请页不能自行切换供货仓库。

准入手机号用于确定员工身份。管理员录入手机号不等于员工已完成手机号验证，员工仍需完成验证码登录。

### 3.6 设置内部登录凭据

仅在员工需要使用管理平台时操作：

1. 在「人员与权限」编辑已有员工，配置其需要的「管理平台能力」并保存。
2. 再进入编辑，点击「设置内部凭据」。
3. 填写内部账号、符合页面要求的临时密码，点击「确认设置」。
4. 将登录信息单独交给对应人员。该人员下次登录须修改临时密码。

设置内部凭据会使该员工的旧管理平台会话失效。工人通过手机号登录小程序，不需要为了申请配送而额外设置内部密码。

### 3.7 提前维护硬件格口与装货点

**硬件格口：**进入「硬件格口」，选择车辆，点击「同步硬件定义」，按提示核对并确认。可编辑本地标签和可用状态，硬件编号只读。同步只是更新格口资料，不会开门。

**装货点：**进入「仓库资料」，点击对应启用仓库行的「装货点」。选择已关联该仓库的启用点位，点击「保存装货点」；可点击「重新读取」核对结果。

装货点表示车辆在仓库装货的位置；工人申请中的目的地表示收货位置。实际装货、选格口和开门操作页目前尚未开放。

## 四、工人操作

### 4.1 登录与选择工作区

1. 打开小程序 H5，点击「手机号验证码登录」。
2. 输入已准入手机号，点击「获取验证码」。
3. 输入环境管理员提供的本地模拟验证码，完成验证。
4. 只有一个角色时自动进入相应工作区；出现角色选择时，选择「工人」。

多角色人员可以在「我的 → 角色工作区」切换。切换前先处理未保存内容，避免丢失正在填写的申请。

### 4.2 提交配送申请

1. 进入底部「申请」，打开「快速申请」。
2. 核对页面顶部显示的「所属仓库」。如果没有仓库，先联系管理员配置。
3. 填写货物名称及描述、货物大小、接收人姓名和接收人手机号；备注可选填。
4. 点击「目的地」，搜索或选择可配送停靠点，再点击「确定目的地」。
5. 点击「预约时段」，选择日期及未来可用时段，确认返回申请页。
6. 核对货物、接收人、目的地和预约时间，点击「提交申请」。
7. 成功后查看提交结果，并到「订单」中核对新订单和订单号。

示例描述可写“演示：维修用轴承 2 箱”，大小可写“每箱约 40 × 30 × 25 cm”。接收人信息应使用本次演练指定人员，不要随意填写他人手机号。

更换目的地后需重新选择预约时段。预约时段表示计划安排，实际配送仍由仓库组织。提交成功只表示申请已保存，后续等待仓库受理。

接收人尚未验证手机号时仍可提交申请，但不因此获得取货权限；当前扫码取货页面尚未开放。

### 4.3 查看订单

1. 点击底部「订单」。
2. 按订单或物料搜索，选择状态后点击「查询 / 刷新」。
3. 点击订单卡片进入详情，查看货物、接收人、目的地、预约时段、取消处理和业务履历。
4. 需要查看最新处理结果时，点击「刷新订单」。列表有更多记录时继续加载。

工人只查看与本人申请或接收有关的订单。没有显示别人的订单属于正常权限限制。

常见状态含义：

| 显示状态 | 如何理解 |
| --- | --- |
| 待受理 | 申请已保存，等待仓库处理 |
| 已受理 | 仓库接受申请，可以继续组织批次 |
| 已驳回 | 仓库未接受申请，应查看处理原因 |
| 已取消 | 取消已生效，以订单最新状态为准 |

如果演示数据中出现“待发车、配送中、待取货、已完成”等后续状态，可查看记录，但当前页面还不能完成对应的全部操作。

### 4.4 申请取消

1. 在本人申请的订单详情中点击「申请取消」。
2. 填写取消原因，按页面提示核对并确认提交。
3. 提交后返回订单详情查看处理情况。

“取消处理中”表示仓库还未给出最终处理结果，不能当作订单已取消；“取消未批准”表示仓库没有同意，应查看原因。取消已批准时，仍以订单详情中的最新主状态和履历为准。

只有系统允许取消时才显示按钮。按钮不显示、订单进入不可处理阶段，或页面要求进一步核对时，联系仓库人员处理，不要反复新建订单替代取消流程。

### 4.5 管理常用停靠点与退出

在「我的 → 常用停靠点」中，对已有点位点击「收藏」或「取消收藏」。显示“收藏已更新”后生效。暂不可用的点位可以移除收藏，但不能通过收藏让其重新可配送。

结束使用时，在「我的」点击「退出登录」并确认。当前浏览器刷新后可能需要重新登录；已成功提交的订单仍然保留。

## 五、仓库人员操作

### 5.1 查看待办与受理申请

1. 使用已授权手机号登录小程序，选择「仓库人员」工作区。
2. 在「仓库工作台」选择「待受理」，或搜索订单/物料。
3. 点击订单，核对货物、接收人、目的地和预约时间。
4. 能够处理时点击「受理申请」，核对后点击「确认提交」。
5. 看到「处理成功」后核对订单状态；已受理订单可在「已受理」筛选中查看。

需要拒绝时，点击「驳回并填写原因」，填写明确原因并确认。驳回必须有原因，方便申请人查看并调整。

订单同时存在取消申请时，原订单受理和取消审核是两项不同操作。先核对申请人的取消意图，再决定如何处理；点击受理不会自动批准取消。

### 5.2 审核取消申请

1. 在工作台查看带有“有待处理取消申请”的订单；必要时切换到「全部」查找。
2. 进入详情，查看申请人的取消原因。
3. 点击「批准取消」或「不批准取消」。
4. 两种处理都需要填写处理原因，再点击「确认提交」。
5. 查看成功提示、取消结果和最新订单状态。

如果批准取消的订单曾加入批次，应重新核对批次成员和装货状态。已锁定或进入后续阶段的业务可能不能直接取消，应按系统提示联系负责人核对。取消单个订单不能当作取消整车任务。

### 5.3 创建配送批次

1. 在仓库工作台点击「查看配送批次」。
2. 点击「创建配送批次」。
3. 从已受理订单中选择需要合并的订单。
4. 核对选中数量、目的地和时段，点击「创建配送批次」。
5. 成功后回到批次列表，核对新批次及成员。

组批必须同时满足：同一仓库、同一目的地、同一预约时段，且订单已受理、未被其他活动批次占用。页面提示“不可选择”的订单不能加入当前组合；找不到订单时先确认已受理，并按需点击「加载更多已受理订单」。

例如，两条申请都是 A 仓配送到 1 号停靠点，预约时间均为同一天 14:00–14:30，受理后可以尝试合并；目的地或时段不同则应分别组批。

### 5.4 编辑已有批次

1. 从配送批次列表点击目标批次。
2. 核对现有成员，选择需要保留、增加或移除的订单。
3. 保持至少一条订单，点击「保存批次成员」。
4. 保存后核对成员数量和状态；需要时点击「刷新最新数据」。

已锁定或关闭的批次只能查看成员。批次成员变化可能使此前的装货确认失效；不能仅凭旧的确认信息继续安排后续操作。

当前页面演练到这里结束。批次创建成功并不表示已经装货、派车或完成配送。

## 六、遇到提示时怎么办

| 页面提示或现象 | 建议处理 |
| --- | --- |
| 未配置所属仓库 | 管理员在「人员与权限 → 编辑员工 → 所属仓库」选择启用仓库并保存；工人回申请页重试 |
| 没有可用停靠点 | 先清空搜索条件；再请管理员检查点位启用、关联仓库及启用车辆的可达点位 |
| 没有可预约时段 | 更换未来日期；请管理员检查营业时段、可预约天数和容量，并确认规则已保存 |
| 所选时段已满或不可用 | 重新选择未来可用时段，核对后再提交 |
| 手机号未准入、账号停用 | 请管理员核对「人员与权限」中的准入手机号、账号状态及业务角色 |
| 验证码错误或过期 | 使用当前演示环境的验证码；按页面冷却时间等待后重新获取，再验证 |
| 没有工人或仓库工作区 | 联系管理员补充相应业务角色；管理平台能力不能代替业务角色 |
| 仓库人员看不到订单 | 核对筛选条件、订单所属仓库及该角色授权范围，不能用工人的所属仓库设置代替审批授权 |
| 订单或批次已被其他人更新 | 查看刷新后的最新内容，再决定是否重新确认；不连续重复提交旧操作 |
| 提交结果尚未确认 | 保留原页面，使用「重试原申请」「重试原操作」或页面提示的原保存按钮；避免重新建立另一条申请 |
| 没有可组批订单 | 先受理订单，检查其是否已占用、是否与当前选择同仓同点同时段 |
| 页面显示功能建设中 | 该模块尚未开放，请参阅下一节；不是当前账号配置错误 |
| 无法打开入口或持续加载失败 | 记录页面提示、发生时间并联系环境管理员；不要自行修改业务数据 |

反馈问题时提供：所在工作区、操作步骤、订单号或批次号、页面提示及发生时间。截图只保留必要内容，不附登录密码或验证码。

## 七、当前使用边界

以下功能尚未形成可供业务人员完成操作的页面流程：装货与格口分配、派车与车辆控制、扫码开门和确认取货、继续出发、异常工单、站内消息、业务概览和业务记录，以及管理端的既有服务接入、基础报表、审计查询。

部分功能已有后台处理能力或模拟数据，菜单也可能已经出现，但业务人员应以页面是否开放为准。本地演示不控制真实车辆、不发送真实短信，也不代表微信真机功能已验收。

## 八、建议的首次演练

1. 管理员核对一个启用仓库、一个可配送目的地和未来预约时段，开通一个工人及一个对应仓库人员。
2. 工人创建两条同仓、同目的地、同一时段的演示申请，记录订单号。
3. 仓库人员查找并受理两条申请，然后创建一个包含这两条订单的配送批次。
4. 工人另建一条演示申请，再提交取消申请；仓库人员填写原因并审核。
5. 工人刷新订单，核对受理、取消结果及业务履历；仓库人员核对批次成员。

完成标准：双方能找到对应订单，看到一致的处理结果，批次中包含预期成员。后续配送、取货不纳入本轮页面演练。
